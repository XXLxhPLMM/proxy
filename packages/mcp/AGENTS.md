# packages/mcp/ — `@b-hole/proxy-mcp`

MCP 服务器（stdio）：把 `@b-hole/proxy` 的控制面交给模型驱动。⚠️ **它驱动的是别的机器上的那个
控制面**，而控制面能读全量配置、增删账号与名单 —— 等价于那些机器上的 root shell。

**这是一个独立包**：⚠️ **不在 `pnpm-workspace.yaml` 的 `packages` 里**（那份只列 `.` 与
`packages/tui`），装依赖要 `pnpm install --ignore-workspace`，且根仓的 `lint` / `typecheck` /
`test` **看不到它的红** ⇒ 改完自己那四条全绿才算完。

## 地图

- `src/protocol/` — **stdio + JSON-RPC 2.0 + MCP 方法分发**（⚠️ 手写，**不许**引
  `@modelcontextprotocol/sdk`：它会拖进 express/hono/zod 一串本包一个都碰不到的依赖）
- `src/api/` — 控制面 HTTP 的**契约**（端点表 / 线格式类型）+ 端点函数（一个端点一个函数，
  ⚠️ 手抄的弱耦合，见下）
- `src/utils/` — `request.ts` 是**唯一**的 axios 拨号点；`json-file.ts` 管两份台账的落盘；
  `errors.ts` 是全部失败词汇（`local` / `wire` / `transport` 三档）
- `src/store/` — `~/.swain-proxy/` 两份台账 + **进程内存**的激活状态 + 「这次动哪几台」的解法
- `src/tools/` — 22 个工具（台账 10 + 操作 12）+ 形参读取器 + 扇出聚合
- `tests/` — vitest 档，见下

## 不可破的事实

### ① key 一步都不出 `@/store/managers.ts`

`key` 就是控制面的 `MANAGER_TOKEN`，等价于主机上的 root shell。⚠️ **明文存** `managers.json`
（没有可加密它的密钥，keychain 要原生依赖），防线是**目录 `0700` + 文件 `0600` + 固定位置 +
`redactManager` 是它离开本层的唯一出口**。故：

- 工具返回值里**永远是掩码 `***`**，连长度都不泄露（不同长度的真 key 不许看起来一样长）
- 失败文案里**不许**出现 `baseUrl` 与 key（它们逐字进模型的上下文，也进 provider 那台机器的日志）
- 牙齿：`tests/tools/ledger-tools.test.ts` 的「① key 的明文一次都不许出现在返回值里」那一档 ——
  含「刚 add 完」「刚 update 完 key」「list」三种时机

### ② 激活**只在进程内存**（`@/store/session.ts`）

推导：落盘会让它跨会话存活 ⇒ 明天开一个新会话、模型还没问任何东西就先打到了昨天选的那批机器上。
⚠️ 代价是显式的（进程重启后归零，模型必须重新激活，而报错文案里就写着该调哪个工具）。
⚠️ **激活存的是名字、不验存在**（存在性由 `@/store/targets.ts` 在使用时判）⇒ 那个设计让
「激活一个不存在的环境」成为可达路径，`env_activate` 因此**当场**验。
⚠️ 正在激活的环境**不许删**（否则下一次调用报「环境 X 不存在」而模型刚才是自己删的）。
牙齿：`tests/tools/wiring.test.ts` 的「激活只活在进程内存」那一档（**起真进程**，同进程内的
调用验不到这一条 —— 内存态的牙齿必须跨进程）。

### ③ 「这次动哪几台」的三条规矩（`@/store/targets.ts`）

| 情况 | 结果 |
|---|---|
| 给了 `managers` | **只**动那几条 —— ⚠️ 替换，不是与环境并集 |
| 没给 + 有激活 | 那个环境的成员 |
| 没给 + 没激活 | ⚠️ **报错给模型**，不静默回退到「全部」 |

三条的代价都写在那份文件头。⚠️ 并集会让「我只动这两台」变成一次**写**打在计划外的机器上；
⚠️ 静默回退最坏 —— 模型以为在动「这个环境」，实际动了全部，而两者在返回结果里长得一样。
⚠️ 悬空 id **当场拒并点名**：环境写面会验，但那份 JSON 可以被手改，而「本来只有两台」与
「有一台被删了」在返回值里完全一样。

### ④ 扇出的三个决定（`@/tools/batch.ts`）

**串行**（写操作序列的顺序是它的语义的一部分）· **一台失败不停整批**（3 成 2 败是一个**成功**
的结果）· **逐台点名 + 失败排在前面**。⚠️ 输出是 **JSON 不是表格**（消费面是模型，表格逼它从
一列宽的文本里再解析一次，那正是「对面的事实」退化成「模型转述的近似」的地方）。

### ⑤ ⚠️ 源码里不许有裸控制字节

本仓的 write/edit 工具会把 `\uXXXX` 转义**还原成真控制字节** ⇒ 文件变成二进制，`git diff`
与编辑器都读不出那一行改了什么。⚠️ 故控制字符判据用 **`charCodeAt` 数值比较**，不用正则
（`@/utils/text.ts`）。自查：`grep` 该文件报 "Binary file ... matches" 就是中招了。

### ⑥ 端点契约是手抄的弱耦合

`src/api/{endpoints,types}.ts` 逐条对照根仓 `src/manager/routes/*.ts` 抄，对面可能跑着旧版本
服务端。⚠️ **只校验信封那几个字段**（`accounts` 是数组 / `account` 是对象 / …），深字段按类型
断言 —— 因为消费面是**模型**而不是终端 UI：某个可选字段对不上时模型看得懂「没有这个字段」，
而一个 TypeError 只会让整个工具调用失败。⚠️ 加端点要同时改 `endpoints.ts` 与 `types.ts`。

### ⑦ ⚠️ 手写 stdio 的一条纪律：stdout 只许写 JSON-RPC

任何日志/诊断一律走 stderr。往 stdout 写一行「加载中」就会让客户端解析 JSON 时炸掉，而那行字
在终端上看着完全正常。⚠️ 一条坏消息**不许**打断整个循环（回 -32700 然后继续读下一行）。

## ⚠️ 错误词汇不许增殖

`McpError` 只有 `local` / `wire` / `transport` 三档，判据是「谁能修」。⚠️ **文案随便改、
`code` 不许新开一档** —— 而「地址指错了服务」与「凭据不对」必须分开（前者要改 `managers.json`，
后者要改 key），故它们分别是 `wire` 与 `wire`（都带 `status`）而靠 `message` 区分。
⚠️ 工具失败**抛**，协议层 catch 后转成 `isError: true` 的 tool result —— 那是模型该读到并据以
改参数的**业务结果**，做成 JSON-RPC 错误等于让客户端把整次调用判成协议故障。

## 测试

- `tests/api/**` — 线路层（打桩是**真 `node:http`**：鉴权头、`Content-Type` 出现时机、4xx 错误体
  翻译、非对象响应体判定，全都在 axios 那一层的后面，mock 掉 axios 就等于把这些一起 mock 掉了）
- `tests/protocol/**` — 协议层（stdio 分片、通知不回响应、一条坏消息不打断循环）
- `tests/ledger/**` — 台账（**坏内容即拒**，且拒完之后盘上那份逐字未变）
- `tests/tools/**` — 工具面（扇出语义、key 不外泄、目标解法、**跨进程**那一档）

⚠️ 家目录靠 `@/tools/host.ts` 的 override 隔离，**不走环境变量**（本包刻意不读环境变量决定
位置，测试若走环境变量就等于给那条纪律开了后门）。⚠️ **激活是进程级的**，每个用例前后都要清 ——
漏清的症状是「一个什么都没做的调用报『没有激活的环境』」，与真正的失败毫无相似之处。

## ⚠️ 假绿的两个已踩过的坑

- **`id` 一律读回来用，不写死**：它是名字的 slug 避让产物（`slugify`），而中文名落不到 ASCII
  slug 时退化成 `m`。写死 `["m"]` 的那一版在换成 ASCII 名字后**静默指向了另一条** ——
  而 `account_list` 照样回一份成功结果。
- **打桩的 handler 要按被测端点答**：`OK_ACCOUNTS` 只认 `/api/users`，拿它去测 `status` 会让
  那一台也 404，于是断言的「失败 1 台」变成「失败 2 台」—— 多出来的那台与被测的那台毫无关系。
