# src/hooks/ — 输入订阅挂在哪儿

三个 React 订阅口，各**只有一处**：键位（`useHotkeys.ts`，本包唯一挂 `useInput` 的文件）、鼠标（`useMouse.ts`，
唯一挂 `mouse.onMouse` 的文件）、终端宽高（`useTerminalSize.ts`，唯一挂 `resize` 的文件）。对外唯一出口
`@/hooks/index.js`。宿主采集与退出边界在 `@/cli.tsx`。

## 层不变量

- ⚠️ **三个订阅口各只有一处**：多挂一处的后果不是「多一次重绘」，是「这份输入/这份宽高从哪来」有了第二个答案。
- ⚠️ **焦点独占的机制就是「全包只有这一个 `useInput`」**：而不是在多个收键者之间调 `isActive`。改动这一条时，
  必须让新来的那个收键者满足下面三件事，否则它会**抢键**且屏上零报错：① 它的每一族键在本层都有对应分支；
  ② 它接管的那一族在本层**先**被判定并 `return`（次序即优先级）；③ 浮层不算模态时，它**不能**无条件吞键。
  ⚠️ 判据是 `tests/input/` 里那 **9** 条键盘第二路径（`Ctrl+X` / `/new` / `Ctrl+R` / `/rename` /
  菜单 `Esc`+`↑↓`+`Enter` / 改名框 `Esc`+`Enter` / **弹窗 `Esc` 两级** / **弹窗 `Ctrl+N` `Ctrl+P` 被改名框吃掉**）——
  加一个收键者就得把这 9 条重跑一遍。
- ⚠️ **那 7 条不是键位分派的全部护栏，而缺掉的恰恰是最容易静默的那几族**：`Ctrl+N` / `Ctrl+P` / `←` / `→` /
  `Home` / `End` / `PageUp` / `PageDown`、窗口里的 `↑` `↓` `Tab`，以及「菜单开着时背后那一层的键照旧走其余
  判据」这一条 —— 它们**一条断言都没有**。⚠️ 证据：把它们连同菜单那一处吞键一起删掉，`pnpm test:tui`
  **一条不红**。⚠️ 而断言喂键时每两个之间都隔 ≥30ms，故「闭包读上一帧 vs 从别处读最新」那个分叉窗口也没有
  断言站在里面。故**加一族键位就得自己补一条断言**（喂那一族键 + 断言屏上后果），别指望已有那几条兜住。
- ⚠️ **不用 Ink 的 `useWindowSize`**：它自带一份兜底（`terminal-size` 再 80×24），会把组合根那份快照在第一次
  resize 之前旁路掉 —— 推导写在 `useTerminalSize.ts` 文件头。
- ⚠️ **少订阅一次 `resize` 的症状不是「不重绘」**：Ink 自己会重排它手里那**上一帧**（按旧尺寸算的那一帧），且
  宽度**变窄**时它先 `clearTerminal` 再把那一帧填回去 —— 屏上于是停着一帧旧布局，永不修复。
- ⚠️ **`columns` / `rows` 只是初值**，而屏上用的是 `useTerminalSize()` 的**当前值**：凡是喂 `geometry()` 与喂
  `<Layout>` 的都读它。拿 props 算 = 「Ink 已按新尺寸重排、本层还按旧尺寸算」的两份几何。
- ⚠️ **输入行有两道闸，顺序是先认领再入状态**：`isMouseReport`（`useHotkeys.ts`）认领终端报文，
  `printableOnly`（`@/lib/input-line.js`）剔 C0 与 `DEL` —— **少任何一道都不成立**（前者不认粘贴进来的 `U+000D`，
  后者挡不住已被 Ink 摘掉 `ESC` 的报文）。
- ⚠️ **模态开着时按键先归窗口**：除 `Esc` / `↑↓` / `Tab` / `Enter` 全被吃掉，且窗口那一支排在任何其它判定之前。
  ⚠️ **`Enter` 走 `enterOutcomeOf(input, cursor)`**（`@/commands/palette.js`）：它是「这一格到底是命令还是聊天」
  的唯一判据，而窗口里高亮那一项的接受与提交输入行必须共用它 —— 各判一次就是两处会分叉的口径。
  ⚠️ **`Ctrl+D` / `Ctrl+R` 只在 `"sessions"` 那一档归窗口**：控制面清单上按它们不该有任何后果，
  而「这一族归不归窗口」的判据必须是 `kind` 本身而不是「窗口开着」。
- ⚠️ **`Ctrl+C` 原样落到本层，而本层刻意什么都不做**：`exitOnCtrlC: false` ⇒ Ink 的**两道**门都不生效
  （`components/App.js:151` 退出、`hooks/use-input.js:104` 跳过监听器；⚠️ 两道都挂在同一个 `exitOnCtrlC` 上，
  改成 `true` 就给退出加了一条绕过「忙就拒绝」那条守卫的后门）。⚠️ 它落进 `if (key.ctrl || key.meta)` 那一族
  而那一族尾部**什么都不做** —— 退出**只经 `/exit` 与 `/quit`**（`@/AppState.tsx:applyEffect` 的 `request-exit`）。
  ⚠️ 判据是 `tests/input/exit.test.ts`「喂 `Ctrl+C` 屏上零变化」：**不是**「源码里没有 `Ctrl+C` 分支」（那种判据恒真）。
  ⚠️ 而那一档的**正向对照与它在同一个 `it` 里**（同一个 handler 喂真键 ⇒ 屏面必须变）：
  「零变化」单独立一条时它对**挂空的实现**恒绿（它只说「没动」）。
- ⚠️ **`down` 的判据次序不可换**：窗口（模态）→ 按键 → **菜单** → 手柄 → 「✕」→ 会话项 → 面板 → 输入行。
  ⚠️ **菜单排在会话项之前**（不是之后）：菜单是浮层，它浮在侧边栏**之上**，而它那一格同时落在某一项的
  矩形里 —— 判在会话项之后的话「点菜单里那一项」会变成「切到它压着的那一个会话」，菜单永远点不动。
  ⚠️ 手柄与那些会话项**重叠**，反过来会让「按着最右那列拖宽」在起手那一瞬把会话切掉。
- ⚠️ **右键只开菜单，不直接动手**（会话项那一份三项：**从侧边栏移出** / 改名 / 新建；空白处那一份只有新建）；
  而菜单**不是模态**：`Esc` 收掉它、点它外面也只收掉它（不顺手把底下那一层点掉），背后那一层的输入照旧走其余判据。
  ⚠️ 菜单里那一项叫「**从侧边栏移出**」而不叫「删除会话」：它是 unpin，`sessions` 与 `messages` 两张表一个字
  都不动；真删是弹窗里的 `Ctrl+D`（级联三张表）。⚠️ 改这个措辞时三处一起改（菜单项、`Ctrl+X` 的说明、这一行）。
- ⚠️ **改名框只住在弹窗里**（`Composer` **不参与**改名），而它的分支仍排在键位分派的最前面
  （`useHotkeys.ts`）：它接管「敲字 / 移动 / 退格 / 回车 / `Esc`」这一整族，
  而漏判的后果是「会话名里混进 `q`」与「回车把它当成一条命令跑了」。
  ⚠️ 因此 **`Esc` 是两级的**：框开着时第一下只关框，第二下才关窗 —— 而那一级差别由
  `editingRename` 回答，不是由「窗口开着」回答。
  ⚠️ 框开着时右上角那枚 `esc 关窗` **不画**（几何层 `windowCloseHint`）：留着就是一句假事实，
  而几何层连列都不为它预留。
- ⚠️ **`move` 与滚轮也归模态门禁**：窗开着时它们背后那一层一格都不许动 —— 症状是「屏上被遮罩压着的
  面板照滚照亮，操作者以为滚轮坏了」。⚠️ 少那道门禁**屏上零报错**（滚轮真的滚了，只是看不见）。
- ⚠️ **只有 `move` 认 hover**：`down` 的命中测试**不看**悬停（悬停状态来自上一次 `move` 事件）—— 一次没有
  `move` 的点击会带着过期的悬停状态进来。
- ⚠️ **滚轮挪窗口、不挪选中**（`AppState.tsx:scrollSessions` 只调 `setSessionsTop`）：翻看别的会话
  不该改「我现在打给谁」，而那一格**加粗**必须留在原地直到点它或 `Ctrl+P` / `Ctrl+N`。
  ⚠️ 反过来几何层**只夹不推**（见上面那一条）：两处各管一件，才不会在下一帧互相拽。
- ⚠️ **点弹窗里那一行的次序是 `windowClose` → `windowInputText`（落插入符）→ `pickWindowRow`**：
  改名框那一格**既**在内容区里**又**是框，而命中测试先认出它是框才谈得上落插入符。
  ⚠️ `pickWindowRow(at)` 的 `at` 数的是**可选会话**而不是「第几行」—— 分组标题行不在其中，
  于是下标与呈现层那份 `pickOrder` 同序，否则点第 2 行会激活到另一个会话。
- ⚠️ **`useMouse` 的依赖表刻意不含 `set*` 与 `resizingRef`**：前者是 React 恒定的 setter、后者是恒定的 ref。
