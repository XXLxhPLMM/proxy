# src/components/ — 呈现层的词汇与整屏的框

本目录回答「屏上有哪些块、每块拿什么、拿到的坐标从哪来」：`types.ts`（组件 props 契约，**零组件**）、
`constants.ts`（两个以上块共用的字形 + `tone`）、`layout/`（整屏那三块：侧边栏底色无关的框、页脚、**模态卡片
的外壳 + 槽位序 + 五个内容渲染器与那个按 `kind` 分派的入口** + 右上角那枚 `esc`）、`index.ts`（唯一出口）。
对外出口 `@/components/index.js`；**组合出口是 `@/app.tsx`**。

⚠️ 「会话栏 / 输入行 / 模型状态行 / 结果区 / 命令面板 / 引导屏 / 用户消息那一块」七块住在 `@/features/`
—— 它们是**功能**而不是**版式**。⚠️ 而**七种弹窗的内容渲染器住在 `layout/`**：它们是「同一块卡片外壳 +
同一份槽位序」的**七种填法**，与版式绑得比与功能紧。

## 层不变量

- ⚠️ **组件一行坐标都不许自己算**：全部读 `props.g`（几何层那一次的结果）；`LayoutProps` 里**没有一个字段是坐标**。
- ⚠️ **输入框是整屏唯一带框的一块**（模态是**没有框**的一块卡片），**状态行在框外**贴着屏底；
  `inputFramed` 由几何层决定，放不下就**如实不画框**。
- ⚠️ **模态卡片：内边距 1 + 标题 + 一道分隔 + 按槽位铺出来的内容区 + 底部留白**。⚠️ **内容区是按槽位铺的**
  （`note` / `group` / `row` / `input` / `select` / `check` **六档**，每档**恒占一行**；能不能被选中由 `kind`
  答，不许由绘制层自己判断）—— ⚠️ 而**六个投影**（`windowRows` / `windowGroups` / `windowChecks` /
  `windowSelects` / `windowInputs` / `windowInputTexts`）**必须由 `windowSlots` 投影出来**，同一个出口。
  ⚠️ 后两个是**数组而单数投影表达不了表单**（那一档有五个字段），故它们**与 `windowSlots` 同序同长**
  （下标 i 就是第 i 个槽位，其余档位给 `null`）——
  「只装得下的那几个」那种形状答不出「第 2 个字段的点落在哪一格」。
  四件事必须从几何层读，不许在组件里算：
  ① `windowContent` 与 `windowBox` **恒不相等**（四边各缩 `WINDOW_PADDING` 再让掉标题那一行）；
  ② 上边那一格 padding 是**一个 `height` 给定的空盒子**（行盒都铺满整块卡片，文字自己带缩进）——
  少它的话内容整体上移一行，而屏上看着只是「标题贴着卡片上缘」；
  ③ 分隔那一行恒是 `MARK_SELECTED` **铺满内区**，而可选行的记号只在左缘一列 —— 「铺满」是它与
  「选中」区分开的那一半；
  ④ 内容区**第一行恒是分隔**，槽位从它下面起铺，而**逐槽**读 `Geometry.windowSlots`（**与入参那串槽位同序同长**，
  装不下的给 `null`）—— 少读一格、或把 `null` 当照画，下面那些行都整体错位一格（屏上只是「少了一行内容」）。
- ⚠️ **一个模态、七种内容、一块外壳、一份槽位序、五个渲染器**：
  `layout/window.tsx` 的 `Window` 只做**分派**（读 `props.view.kind`，判别字段与 `@/store` 的
  `WindowState.kind` **逐字同名**），五个内容渲染器各占一个文件、**互不 import**
  （`window-sessions.tsx` 的分组标题与改名框 / `window-list.tsx` 的连接字形与「←当前」记号 /
  `window-provider-form.tsx` 的字段与下拉 / `window-provider-models.tsx` 的过滤框与勾选位 /
  `window-models.tsx` 的 `★` 与跨组高亮 —— 每一族只有那一档答得出）。
  ⚠️ **`targets` / `users` / `providers` 三档共用一个渲染器**（行模型 `ListRow` 逐字相同，差的只是动作；
  分三个渲染器的话「清单那一行怎么画」就有三份实现）⇒ 于是是**五个**而不是七个。
  ⚠️ **分派不收窄**：收窄是**类型**上的事（各渲染器自己判 `kind`），两处各算一次判据的话加一档时
  有一处静默不画 —— 症状是「按了没反应」而屏上零解释。
  ⚠️ **外壳一个视图都不提**（`window-card.tsx` 不认识 `ModalView`）。
- ⚠️ **槽位序只有一个出口**（`layout/window-slots.ts` 的 `slotsOf(view, rename)`）：
  `@/app.tsx` 拿它喂 `geometry()`，五个内容渲染器拿它读 `windowSlots` —— 三处各算一次的话
  「画在第几行」与「点在第几行」会错开一格，而屏上完全看不出异常。
  ⚠️ **它接两个入参而改名框那一格不属于视图**（`LayoutProps.rename` 住顶层：焦点在框上这件事屏上到处都要读）
  ⇒ 撤掉改名框那一格时槽位序真的短一格，而槽位序从视图里读它就撤不掉。
  ⚠️ **两处次序是被咬过人的**：表单的说明**排最后**（排前面的话校验失败一次那五行整体下移一格 ⇒ 每按一次
  `Enter` 字段跳一次）；模型清单的过滤框**恒占第 0 槽**（哪怕词是空串 —— 它恒在键盘焦点上）。
  ⚠️ **表单那五格的顺序是「地址 / API 格式 / id / 名称 / key」**（`AppState.tsx:PROVIDER_FIELDS`）——
  地址在前因为它是第一个要填的，`key` 在后因为它常常**留空不改**；换序的话「填完前四格按 `Enter`」
  这一串手势就落到别的格上，而屏上零报错。
- ⚠️ **表单校验不过就**不关窗**，而说明行说清哪一格不对且**不转述用户输入**（文案逐字取自 `@/services/config`
  的校验面）：无条件关窗与「提示错了」在屏上分得开 —— 前者整块卡片不见了，操作者不知道自己填错了哪一格。
- ⚠️ **焦点格的插入符与改名框、`Composer` 是同一套画法**（反底色块 = 颜色之外的形状通道）：
  判据是**两个条件同时成立** —— `kind === "input"` **且** `focused`。⚠️ **`select` 那一格恒不画**
  （下拉里没有一段用户敲出来的字，画它等于说「这里能落字」）；⚠️ **非焦点那一格也不画**
  （留在屏上的反底色块等于说「焦点还在那儿」）。⚠️ **凭据那一格留空 = 不改**：它的 `value` 恒是掩码或空串，
  插入符落在第 0 格正是「空着等你敲」，而**不许**为了让它好看而拼一个可见的假值上去。
  ⚠️ **那一格先占住宽度再裁前半段**（与改名框同一条纪律）：反着算的话光标很深时前半段顶到右缘 ⇒
  **整行超宽** ⇒ Ink 静默软换行（卡片里多出一行而下面那些掉出去）。
- ⚠️ **右上角那枚 `esc` 提示没有悬停态**：它恒是卡片那一档底色，而**按键字形与动作文案必须不同色**
  （同色 = 「按哪个键」与「会发生什么」读起来一样）。⚠️ 它的位置读 `Geometry.windowClose`，而标题的裁剪
  预算读 `Geometry.windowTitle`（已让开它那几列）—— 两处各减一次就是长标题压住 `esc`。
  ⚠️ **画不画它只读 `windowClose === null`**（几何层才是「它占不占列」的真相），而 `windowClose === null`
  同时意味着标题能用满整行。
- **选中态没有反底色**（最亮那一档 + 加粗），那一列的底色归 **hover** —— 「我选了哪台」与「指针在哪」是两个通道。
- ⚠️ **「待确认删除」整行换 `danger`**（两段 `Ctrl+D` 里已经按过第一次）：只给名字换档的话右边那一段说明仍是
  常态色，那一行看着与平常一样。⚠️ 它与悬停那枚 `✕` **同一档** —— 屏上两处说的是同一句「别按」。
- ⚠️ **勾选位刻意是纯 ASCII**（`[x]` / `[ ]`）：`☑` / `☐` 的 East Asian Width 是 **Ambiguous**
  （按 CJK 宽度渲染的终端里是四列）而 `string-width` 按三列算 ⇒ 少算的话那一行的列位在两帧之间跳、点它落错行。
  ⚠️ 而**置顶那一枚用 `★`**（与勾选位的 `[x]` / `[ ]` **形状不同**：它答「这行排在最前」、勾选答「它被选上了」，
  高亮答「焦点在这儿」—— 三件事三个通道）—— ⚠️ 两枚字形**不许合并**成同一枚：合并之后
  「置顶且被选中」那一行就与「只是被选中」那一行在 `NO_COLOR` 终端里同形。
- ⚠️ **`/models` 那一档的 `↑` `↓` 在**可选项**之间跨组连续**，不按组重启**：分组标题不是可选项，
  而按组重启的话每滚到一个提供商的开头就跳回它自己那一组 —— 清单长起来之后根本滚不到底。
  ⚠️ 判据形状是「下标数的是**可选项**而不是「第几行」」，与 `pickWindowRow(at)` 同一条纪律。
- ⚠️ **模态窗口开着时背后那层的点击、悬停与滚轮全被吞掉**（`@/hooks/useMouse.ts` 三个分支都门禁），
  `CloseChip` 画在**那个分派入口**之后（Ink 后写的赢）。
- ⚠️ **Ink 没有半透明，遮罩是「重新铺一层不透明底色」**：**任何自己带底色的盒子都会盖在它上面**，**任何带边框的
  盒子都会把它挖空**（`render-border` 只读节点自己的 `borderBackgroundColor`，**不继承**祖先底色）。症状全是
  「屏上看着没毛病」（整屏压暗了而侧边栏没压暗、屏最底下横着两条亮线）⇒ **判据只能逐格比两帧**
  （`tests/layout/window.test.ts` ⑥）。⚠️ **七档都要跑这一遍**：只测一档的话其余六档是零鉴别力，而症状一模一样。
  ⚠️ **新弹窗里那些 `input` / `select` / `check` 槽带底色的盒子也在卡片内部** ⇒ 它们盖在遮罩**之上**是对的，
  而「挖空」的担心只在**输入框那一圈边框**上（那是 `Composer` 的活）。
- ⚠️ **侧边栏那一列：四项必须一起记** — ① `sidebarRows[i]` 是第 `sessionFirst + i` 个会话（`SessionSidebar`
  的切片与 `@/hooks/useMouse.ts` 的每一处回查都要加它，漏一处的症状是「画的是会话 3、点的是会话 1」而全屏零报错）；
  ② **顶部留白 {@link SIDEBAR_TOP_PAD_ROWS} 行、项与项之间空一行**：那两个留白盒子必须由 `SessionSidebar`
  显式画出来（几何给的是 `SIDEBAR_TOP_PAD_ROWS + i * SESSION_STRIDE`，少一个盒子时每一项都比几何给的行号
  高一行，而症状是「点第二项切到第三项」）；
  ③ **记号位那 3 列与关闭那 2 列恒预留**，名字的裁剪预算恒扣掉它们（**恒**，不是「画得出才扣」），与
  「指针在哪儿」和「有没有记号」都无关（悬停只决定**画不画**那枚 `✕`，`idle` 只决定那一格是不是空格）；
  ④ **选中只高亮标题那一行**：第二行恒用 `idle` 且不加粗 —— 两行都高亮的话「我选了哪一项」与「它连着的
  那台是当前那台」在屏上读起来一样。
- ⚠️ **`SessionMenu` 排在 `Layout` 的最后**：它靠「后画的赢」压住侧边栏与输入框，而它**没有遮罩**
  （菜单不是模态：点它外面就是关掉它，背后那一层照旧可见）。⚠️ 它**没有边框**（一圈框线只会把它画成
  「另一个终端窗口」），而它的每一项读 `Geometry.menuRows` —— 画不出来的那一项**不许**多画。
- ⚠️ 溢出说明行是判据而不只是坐标：呈现层按 `sidebarOverflowRow` 是不是 `null` 决定画不画那句话，而它的
  文案**必须跟着窗口滚**（写死首项号的实现会在滚过之后说「1–5」而屏上是 3–7）。
- ⚠️ `SessionSidebar` 那一列的底色只给**外层**那个 `<Box>` 一次（内层 `<Text>` 从父继承，而悬停的那一项自己
  再给一层 `hover`；⚠️ `hover` 必须**比 `surface` 深**，选色见 `@/theme/AGENTS.md`）。
