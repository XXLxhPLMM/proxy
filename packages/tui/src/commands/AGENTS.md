# src/commands/ — 命令层（表 + 分词 + 补全 + 面板）

**零终端、零 React、零 HTTP、零 `fs`** —— 于是它能在一台没有终端的机器上被逐字断言。对外唯一出口
`@/commands/index.js`。

| 文件 | 答什么 |
|---|---|
| `specs.ts` | 那张唯一的命令表（`COMMAND_SPECS`）、形参声明（`arg` / `opt`）、用法串、名字查表 |
| `values.ts` | 形参的**值语法**：流量单位、控制面名单、各 reader |
| `parse.ts` | 分词（`tokenize`）、命令名解析与元数检查、`parseLine` |
| `suggest.ts` | 拼错时的建议（编辑距离 + 公共前缀） |
| `complete.ts` | Tab 补全**形参的值** |
| `palette.ts` | 命令面板 —— 只管**命令名**，外加 `Enter` 那一档的结论（`enterOutcomeOf`） |
| `index.ts` | barrel，只转发 |

## 层不变量

- ⚠️ **表里没有组**：所有列表型操作都在弹窗里做完（弹窗由状态层直接调读写面），
  于是「命令名」**恒是一个词** ⇒ ① 解析层只查**第一个词**（多敲一段落到「多给了 N 个参数」那一档，
  那是对的处理）；② 面板的命令名段就是第一个词；③ `PaletteRow` 上**没有**「补不补空格」那个字段
  （命令名带空格的日子过去之后它恒假，而恒假的字段比没有更坏：它看起来像一道还在生效的闸）。
  ⚠️ 牙齿：`tests/parse/command-table.test.ts`「**表里没有组**」那一组。
- ⚠️ **每一行命令都以 `/` 开头**（`COMMAND_PREFIX`），给人看的命令名只有 `CommandSpec.path` 一个出口 —— ⚠️ **不许「宽容地」接受不带前缀的写法**，否则这条形状不变量一句牙齿都没有；牙齿在 `tests/parse/command-table.test.ts` 末尾那组断言。⚠️ 而**输入行上不以 `/` 开头的那一行**不是解析失败 —— 它是**一句普通聊天消息**（走模型，`packages/tui/AGENTS.md`「模型」一节），判据是那**一个字符**。
- ⚠️ **弹窗那一族的 `summary` 必须把键位说全**（`↑↓` 选 · `Enter` · `Ctrl+A` 新增 · `Ctrl+D` 删除（按两次）·
  `Ctrl+E` 编辑 · `Esc` 关窗，各命令另有自己的几个）—— **那是屏上唯一一份键位说明**，而弹窗自己不会解释
  「我按了它怎么没反应」。牙齿：`command-table.test.ts`「把键位说全了」那一组（逐条点名每一个键）。
- ⚠️ **`ArgSpec.rest` 那一格吃下**剩下的原文**（今天只有 `/batch <控制面> <命令>`）：分词再拼回去会毁掉引号，
  而内层命令的形参于是错位。⚠️ 「多给了几个参数」那道个数判据
  **必须**在 `rest` 之前分岔，否则 `/batch all /help "user add"` 会被判成「多给了 3 个参数」。
- ⚠️ **`/batch` 的 `build` 交出 `BatchDraft` 而 `parseLine` 递归解析内层那一条**（`resolveDraft`）：
  解析层是**唯一**认识 `parseLine` 的地方，而这张表是它的**下游** —— 两处各解一次就多了一条判据会漂的缝。
- ⚠️ **失败文案绝不引用用户输入**：`ValueError` 只说「哪个形参期望什么形状」，因为它会落进**可滚动的结果区**，而台账名字与粘贴进来的那一串会经过这里。
- ⚠️ **零兼容不留别名**：删掉的命令连旧名都不留（`/managers` → `/targets` 这类改名也不留转发），
  而别名是最容易被"顺手加回来"的东西（它看起来像「兼容老脚本」）。牙齿：`command-table.test.ts`
  「零兼容」那一组（逐条点名那些敲得出来的旧串 + 一组正向对照）。
- **面板开不开只看「输入行里有没有 `/`」**（`palette.ts:paletteOpen`），高亮是**输入行的纯函数**，
  `↑`/`↓` 走完之后把那一行**写进输入行** —— 于是「输入行上敲的是 A、面板高亮的 B」在类型上不可能。
  ⚠️ 而**完全相同的那一条优先于「以它开头」**（`/r` 高亮到 `/r` 本身而不是 `rename`）—— 反过来 `Tab`
  会补出一条他没敲的命令，而那一条还真实存在。
- ⚠️ **`Enter` 的结论只落在「接受高亮之后**命令名**变没变」**（`palette.ts:enterOutcomeOf`），**不是**「命令名敲全了没」，也不是「光标动没动」，也不是「形参的值补没补」（那是 `Tab` 的活）：
  - ⚠️ 「敲全了没」会把 `/help` 判成「该补全」——而高亮**就是它自己**，于是屏上那一帧是「按了回车没反应，按一百次也没反应」。
  - ⚠️ 「光标动没动」不是判据：拿它当判据就是给 `paletteFill` 的算术瑕疵发绿牌。
  - ⚠️ **顺带调 `complete`** 也不行：形参的值补全是 `Tab` 的活，而 `Enter` 是「跑掉」那一下。
  - ⚠️ **三档 `submit`**：面板关着 / 开着而没有高亮 / 开着而接受之后命令名逐字相同。它们合成一档是因为调用方对它们的处置**是同一件事**（把这一行交给解析层），而「有没有高亮」区分不出后两档 —— `/help` 是有高亮的。
  - **代价是数出来的（四档并成两档，全是一下）**：单段零形参 1 下、单段带形参 1 下。⚠️ 判据是
    `tests/palette/enter.test.ts`「从敲第一个字到跑掉要按几下」那一档，它**逐条重算全表**并**按命令表那份
    形参表分档**。⚠️ **半截名字仍是两下**（补一次 + 提交一次），而**跑掉的是补全出来的那一条**。
- ⚠️ **补全只重写光标所在的那一个词**，光标之后的字节逐字不变（`complete.ts`），候选只来自命令表声明的 `choices` —— ⚠️ **不许读台账**（台账名字只从 `CompletionRequest.targetNames` 进来，而命令表里**只有 `/batch` 第一格**读它）。
