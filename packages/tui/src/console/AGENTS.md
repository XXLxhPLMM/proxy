# src/console/ — 全屏 console（几何 / 行模型 / 执行 / 布局）

本目录是**呈现与执行**这一侧：`geometry` 算屏幕坐标，`log` 把命令产出摊平成可滚动的行，
`exec` 执行命令并说清发生了什么，`layout` 把状态画成一屏。对外唯一出口 `index.js`（跨目录只引
这一个 barrel）。

⚠️ 目录形状对应一屏的四件事，且**四者共用同一份坐标**：画在哪（`layout`）与点在算哪（`geometry`
的 `hitTest`）必须逐字一致，而它们俩共用 `geometry()` 那一个纯函数 —— 详见 `geometry.ts` 的文件头。

## 文件

- `geometry.ts` — **屏幕几何的唯一真相来源**：侧边栏 / 目标行 / 结果区 / 输入区 / 输入行文本区
  以及**命令面板那几行候选**的每一个 `Rect`（⚠️ **没有顶栏**：屏顶那两个框从第 0 行起），
  加 `hitTest`（半开区间、后一个赢）与 `caretFromColumn`（按**显示列**定位插入符）。
  ⚠️ 第四个形参 `paletteCount` **没有缺省值**：它必须由每一处调用点显式给，而两个调用点
  （`@/app.tsx` 与 `layout.tsx`）读的是**同一个** `paletteView`，故两份结果逐字相同。
- `log.ts` — **结果区的条目模型**：`LogRow` 六类 → {@link flatten} 摊平成行 → `visibleLines` /
  `clampTop` 滚动；`append` / `trim` / `dropped` 是环形缓冲；`maskEcho` 是全包唯一的凭据掩码出口。
- `exec.ts` — **命令执行层**（一条命令 → 若干行 + 一组 `Effect`）。**零 React、零状态**。
- `layout.tsx` — **唯一挂 Ink 的文件**：把几何与状态画成一屏（本包其余部分都不画东西）。
- `index.ts` — 目录 barrel，**只转发**。
- `AGENTS.md` — 本文件。

机制与决策的完整推导在各文件头（`@fileoverview` / `@description`），这里只列**不变量**。

## 层不变量

- **`geometry.ts` 是渲染与命中测试的唯一真相来源**：全部坐标由 `columns` / `rows` 与几个常量**算术**
  得出，**不接受任何「Ink 会替我算」的前提**。代价是排版不再有弹性（一个 `<Box flexGrow>` 本可以
  自己适应），换来的是「画的」与「点的」在类型上就不可能不一致。
  ⚠️ 反过来说：**本目录不许出现第二份 `Rect` 或第二个 `hitTest`** —— 同名同签名而分处两个目录，
  改了一份忘了另一份，症状就是「键盘能选中 A、鼠标能选中 B」，一种无从归因的错。
  （本包历史上真的有过第二份，在 `@/ui/mouse.ts` 里，已删。）
- **本包刻意不用 Ink 的 `measureElement`**：它的文档说它给的是 layout-tree 坐标、需要用活动区域
  原点平移 —— 那是**它**的坐标需要平移，不是**鼠标**的。鼠标坐标是终端**屏幕**坐标，与
  {@link Geometry} 算出来的矩形**已在同一套坐标里**。两者弄反的后果是给每一次点击加一个根本不存在的
  偏移，于是「点哪都不对」而每个部件单独看都合理。
- **`layout.tsx` **不认识**控制面数据的字段语义**：它只认 `LayoutProps` 里那些**已经排好版**的字符串
  与 `SidebarItem`（`name` + `state`）。数据怎么变成字符串是 `exec.ts` 的事。
- **每一行都裁到它的可用宽度**：Ink 对过宽的 `<Text>` 是**静默软换行**，一换行整屏就往下移，而屏幕
  上没有任何东西解释它去哪了。⚠️ 三处各扣各的：侧边栏的名字预算（`NAME_BUDGET_OFFSET`）少扣两列就会
  让**一整块框顶歪**（而它在短名字那一档完全看不出来）；输入区那两行的预算少扣**右边框那一列**就会
  在「拉到最满」时压到边框上。牙齿：`tests/layout.test.ts` 的「长中文名」与「每一行都不超宽」那几条。
- **文字的真实起点 = 框的 x + `BORDER_LEFT_COLUMN` + 缩进**：⚠️ Ink 的 `<Box>` **没有默认内边距**
  （`padding` 不在 props 里就整条不执行），故左边框那一列是**真的**。少算它一列，症状不是「命中区域
  偏了一格」这么轻 —— 它让「点某个字得到的是它**右边**那个位置」，而插入符落在相邻两字之间时终端上
  看不出差别。牙齿：`tests/layout.test.ts` 不变量 ⑩ 断言**渲染出来的字符列号 == 几何给的 `x`**
  （而不是「两个常量相等」—— 后者对「两个一起错一列」恒绿）。
- **屏顶没有横向区域**：那两个框从第 0 行起、铺满整屏，会话级事实（版本号、控制面数量）在**底部状态行**
  的右半。⚠️ 顶上再开一行放它们，等于花掉整屏最贵的一行（在 2–3 行的屏上它就是「结果区有没有内容」）
  去重复屏幕上已经有的信息。牙齿：`tests/layout.test.ts` 不变量 ⑨「屏顶没有横向区域」。
- **侧边栏不画右边框**：主区那个框的左边框就紧挨着（`mainX === sidebar.width`），两个都画会在屏上
  留下**两根并排的竖线**。⚠️ 而 {@link Geometry.sidebarRows} 那一列的 `- 1` 仍然是对的：那一列
  现在是**主区的左边框**，点它不该选中任何一行。
- **选中态是一段连续的反底色**（记号 + 空隙 + 字形 + 空隙 + 名字**一个 `<Text>`**）：拆成三段的话
  字形那一格不在反底色里，而侧边栏的唯一职责就是回答「现在是哪一台」。牙齿：同档那条
  「每一个格子都在反底色里」—— 它需要真的解析 SGR 参数（判据与它的两个陷阱见该文件）。
- **命令面板**（`Layout` 的 `palette` prop）**接管**结果区，与 `Output` / `Welcome` **三取一**：
  三者画在同一块矩形里，而 Ink 对多出来的子元素只会**往下堆**（不报错），症状是「面板开着、
  上一条命令的结果还露在它上面」。⚠️ 而它**复用** `Geometry.output` 而不是另开一块（理由写在
  `geometry.ts` 的 `paletteRows` 那条注释里）：另开一块的话每敲一个字符结果区就矮一行，
  操作者看着输出被一格格挤走。
- **面板那几行的名字与说明各自有预算，且加起来恒落在内容宽度内**：名字是「这一屏最长的那个
  命令名」与「半屏」取小，说明拿剩下的。⚠️ 少了那个封顶，一条很长的命令名会把说明**整列挤没**
  —— 而说明正是这块面板存在的第二个理由（牙齿：`tests/layout.test.ts`「命令名很长时」）。
  ⚠️ 高亮那一行的记号 / 名字 / 说明**三段同一个背景色**：拆开的话高亮断成两截（与侧边栏同源）。
- **滚动位置那一行永远在**：结果区底部固定一行说「上面/下面还有多少」。⚠️ 不画它的话，
  「已经到底」与「下面还有内容没显示」在屏幕上长得一样。⚠️ 而「丢弃过历史」与「现在在哪」是**两句
  独立的话**：把前者写成后者的一部分会让**顶部**那一帧骗人说「上翻」。
- **装不下必须说一声**：侧边栏装不下的目标给出「…还有 N 个」，结果区丢过历史给出「已丢弃」。
  静默少画几行/少记一段，操作者会以为台账就这几个、历史是完整的。
- **底部状态行的两半各说各的**：左半「连的是哪台机器」（会随选中变）、右半「会话是什么」
  （`v… · N 个控制面`，**恒定**）。⚠️ 左半**按右半占的宽**裁 —— 反过来就是窄终端里先牺牲「我现在连的
  是哪台」，而那一半是每敲一条命令都要用的。⚠️ 同一个数（一屏里的控制面数量）**只许出现一次**：
  侧边栏标题下**没有**第二行数字，写两处就要操作者去比它们。
- **`exec.ts` 不碰状态**：不 `setState`、不写台账、不改当前目标。它只发请求、只读注入进来的东西，
  然后**说**发生了什么（`Effect`）。⚠️ 理由不是洁癖，是可测性：执行层一旦改状态，它的每一条判据都要
  起一次真界面才能断言。
- **没有客户端时**需要控制面的命令只回一句「先在左边选一个控制面」，**一个请求都不发**：
  对着 `0.0.0.0:0` 发一次会把「你没选控制面」显示成「那台机器连不上」—— 后者是一句**假事实**，
  且它会把人带去查一台根本没问题的机器。⚠️ 判据是**穷举的 `switch`**而不是一张「哪些命令要客户端」
  的清单：加一条命令时忘了往里加一项编译期不会红。
- **逐字限定不许改写**：`runningMeans` / `notice` / `effective` / `lagMs` / `sideEffect` / `note` /
  `TuiError.message` 全部原样上屏 —— 措辞是**服务端**的知识，本层改写等于宣称「我知道这是什么」。
  逐条清单在 `exec.ts` 文件头（十条）。
- **`changed: false` 是成功**（一次成功的 no-op）：渲染成错误会让操作者以为操作没成；显示成「已改」
  是一个字节都没动的事实在撒谎。故 `effective` **只在** `changed: true` 时显示。
- **凭据不进任何一行**：`user pass` / `user set … password` / `target add` 的密码与 token 只以掩码
  形态出现在回显行（`log.ts:maskEcho` 是全包唯一的掩码出口），**任何失败文案也不许带它**。
- **滚动位置永远以行为单位**：`flatten` 的行高依赖**显示宽度**，所以摊平结果**不能跨宽度缓存**。
  两套单位（按条目 / 按行）混用是滚动错位的唯一来源。
- **命令表只有一份**（`@/cmd/index.js:parse.ts` 的那张表），本目录**只读它**不抄第二份；
  `user set` 的字段表也**只**住在那里（`exec.ts` 按 `field` 穷举分派并以一条 `never` 断言收尾）。

## 已知缺口（是「不变量」，不是「没来得及」）

- **`Geometry` 不表达「重叠」**：侧边栏那个框与主区那个框在几何上是**两个矩形**（宽度加起来正好是
  终端列数），但它们各自还有上下框。命中测试对**同一层**是后一个赢，而跨层的重叠（框画在框上）
  本目录**没有**判据 —— 因为没有任何一次点击应该同时命中两层。
- **滚轮一格 = 三行**（`SCROLL_STEP` 在 `@/app.tsx`）：滚轮设备的「一格」在不同终端上不是一个统一的
  物理量，故这里取一个「不至于一滚穿过整屏、也不至于一滚只动一行」的数，而不是假装知道设备的精度。
- **`flatten` 每帧重算**：结果区是环形缓冲（2000 条）而不是虚拟化的。⚠️ 每帧 O(全部行) 在 2000 条
  以内是毫秒级；哪天真慢了，该换的是「只重算视口那几行」，而那要求摊平结果能增量维护 —— 那时
  `flatten` 就得知道视口，而它现在**刻意不知道**（`visibleLines` 才是切视口的那一层）。
- **极矮 / 极窄终端（1–3 行、少于两列框宽）画不出完整布局**：各区高度夹到 0，框画不下就**不画框**。
  这是**诚实**的 —— 比在 3 行里硬塞三样东西、或在一列宽的屏里渲染出一个越界的框要清楚。
  ⚠️ 框越界这一条尤其要守住：「每一行都不超宽」是本包用来逮「Ink 静默软换行」的那把尺，
  尺自己越界之后每一条宽度断言都跟着失效（牙齿：`tests/layout.test.ts` 的 `columns=1 rows=1`）。

## 相关路径

- `@/console/index.js` — 本目录**唯一**的出口（跨目录不许引深层路径）。
- `@/cmd/index.js` — 上游：`Command` 判别联合与那张**唯一**的命令表。
- `@/client/index.js` — 上游：响应体形状、`ManagerClient`、`TuiError`。
- `@/ledger/index.js` — 上游（**通过** `@/app.tsx` 注入）：台账的写与客户端的构造都在那一层。
- `@/ui/index.js` — 排版与着色的判据（`ellipsis` / `widthOf` / `planColumns` / `themeOf` /
  `connectionStateOf`）与 `BANNER` / `TAGLINE`。
- 根仓 `src/manager/routes/*.ts` — 服务端真值：`patch.ts` 的 `PATCH_KEYS` 就是
  `@/cmd/parse.ts:USER_FIELDS` 镜像的那一份。
