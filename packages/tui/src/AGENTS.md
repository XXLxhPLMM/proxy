# src/ — 组合根（宿主采集面 + 应用状态层）

`src/` 根上的三个文件就是本包的全部骨架：`cli.tsx` 采集宿主来源并接管终端，`app.tsx` 持有**全部**
跨帧状态并把骨架装起来，`index.ts` 是包入口。**它们一个字的数据形状都不认识** —— 控制面数据的形状
全在 `@/api`（怎么变成一行字在 `@/exec/run.js`）。

## 一屏长什么样

```
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│❯ /status▌                          ← 输入行里有 `/` ⇒ 面板浮在下面那几行 │
▓▓ live-ok   ● ▓▓▓▓▓│ 进程    running    pid 12345                              │
▓▓ bad-token ▲ ▓▓▓▓│ 名称    状态    上限      本月用量                          │
▓▓ no-server ○ ▓▓▓│ alice   启用    1.0 GB    128.4 MB                         │
▓▓ …还有 2 个   ▓▓▓│  ⇅ 下方还有 12 行 · PgDn 下翻                            │
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│ ▍ /help    列出命令，或给一条命令看用法                      │
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓╭────────────────────────────────────────────────────────╮ ← 输入区（**整屏唯一带框的一块**）
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│ ❯ /user add charlie▌                                         │
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│   执行中：/status                                          │
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│   http://127.0.0.1:18080 · 超时 5000ms      v5.2.0 · 3 个控制面 │
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓╰────────────────────────────────────────────────────────╯
```

⚠️ **命令面板**（`@/cmd/palette.js`）：**输入行里有一个 `/` 就浮出一块面板**，逐行「命令名 + 说明」，
可上下走、可用 `Tab` / 鼠标点接受。⚠️ **判据只有这一条** —— 光标在哪、有没有敲完一个空格，都
**不影响**它开不开：那些附加条件各自都能说通，合起来却会造出「有时候有面板有时候没有」的**第二种**
面板，而屏上没有任何东西解释那个「有时候」。它换来的一条不变式是「**面板开着 ⇒ `↑`/`↓` 归面板**」
（否则它们切目标，而「切目标还是选命令」是最不该让操作者猜的一件事）。
⚠️ 它**浮在输入框正上方**、高度**至多**结果区内容行的 40%（连同那一条「装不下」说明行算在一起），
而**结果区仍在它上面**（至少六成）—— 一边挑命令一边看上一条命令的结果，两件都要的事。
⚠️ 短列表时面板**按实际条数**高（不撑满那 40%），否则它下方会留一大片什么都没有的空白。

⚠️ **底部那一行不再列命令**：瞬时消息只剩两档（`执行中：` 与一条自生自灭的消息），原来那档
「Tab 补全：quotaBytes quotaWindow」被删掉了 —— 它曾经是「有哪些命令能敲」的答案，而那块答案
现在是**命令面板**。留着它就是同一件事在一屏里出现两次（面板列**全部**命令、那一行列**光标位置**
的候选），而两处的排序规则本来就不同（面板按表的顺序、候选按字典序），操作者会去比它们。

⚠️ **屏顶没有横向区域**：会话级事实（版本号、控制面数量）都在**底部状态行的右半**，而「现在是
哪一台」由侧边栏那一项的**文字颜色**回答。⚠️ 顶上再开一行放它们，等于花掉整屏最贵的一行（在 2–3 行的
屏上它就是「结果区有没有内容」）去重复屏幕上已经有的信息。⚠️ 侧边栏**顶部也没有标题行** ——
那里直接就是目标清单，而目标数一屏里只出现一次。

⚠️ **没有「页面」**：本工具的全部功能是**命令**（`@/cmd/index.js` 那唯一一张表），而结果区与输入区
是**同一块主区**的上下两半。⚠️ 这条不是风格选择：一个页面就是「当前在哪 + 这一页的键位 +
这一页的数据」三件套，而这里「当前在哪」只有一个答案（结果区里最近的那些行），键位只有一张
全局表，数据一律由命令现拉。故 `1`-`6` 是**命令里的字符**，不是页签序号。
⚠️ **没有「页面」**：本工具的全部功能是**命令**（`@/cmd/index.js` 那唯一一张表），而结果区与输入区
是**同一块主区**的上下两半。⚠️ 这条不是风格选择：一个页面就是「当前在哪 + 这一页的键位 +
这一页的数据」三件套，而这里「当前在哪」只有一个答案（结果区里最近的那些行），键位只有一张
全局表，数据一律由命令现拉。故 `1`-`6` 是**命令里的字符**，不是页签序号。

## 文件

- `cli.tsx` — **组合根**：采集宿主来源（`env` / `os.homedir()` / 终端**宽高** / `NO_COLOR` /
  版本号）→ 算台账路径 → `enterFullScreen` → `mouse.start()` → `render(<App …/>,
  { alternateScreen: true })` → 三条退出路径共用一个幂等 `finish()`。**import 期零副作用**；
  ESM 的入口判据是 `import.meta.url` 与 `process.argv[1]` 的 `file:` URL 逐字相等
  （本包**没有** `require.main`，代价写在文件头）。
- `app.tsx` — **应用状态层**：台账（含 `ledgerError`）、当前目标、**每个目标最近一次探活持有的
  那个值**、**每个目标一个输出桶**（条目 + 滚动位置 + 贴底标记）、输入行（串 + 插入符下标）、
  补全建议、瞬时消息、正在跑的那条命令。组装 `@/view/layout.js` 并持有**键位**与**鼠标分派**。
  **探活的唯一发起方**。⚠️ **它没有 `quit` 这个 prop**：`Ctrl+C` 由 Ink 自己在把输入交给任何
  监听器之前处理掉（理由在 `app.tsx` 文件头）。
- `index.ts` — 包入口 barrel（只转发 `App` / `main` 与它们的类型）。
- `AGENTS.md` — 本文件。

## 子目录

- `client/` — 控制面 HTTP 客户端（端点表 / 线格式 / 失败三档）；见 `client/AGENTS.md`。
- `cmd/` — 命令表 + 分词 + Tab 补全 + **命令面板**（`palette.ts`）（**零终端、零 React、零 HTTP**）。
- `console/` — 全屏 console 的呈现与执行（几何 / 行模型 / 执行 / 布局）；见 `console/AGENTS.md`。
- `ledger/` — 本机台账（存盘、校验、接线、探活）；见 `ledger/AGENTS.md`。
- `ui/` — 排版与着色的判据 + 全屏接管与鼠标协议；见 `ui/AGENTS.md`。
- `tests/` — 本包的 vitest 档（`pnpm test:tui`），含一档**假 TTY 真渲染**。
- `dist/` — `build.mjs` 的产物（gitignored）；**不**在运行时地板扫描面里。

## 层不变量

- **组合根是唯一的宿主采集面**：`process.*` / `os.homedir()` / 终端宽高 / `NO_COLOR` / 版本号
  **只在 `cli.tsx` 采一次**，全部当 props 往下传（`@/ui/theme.ts` 文件头那条纪律）。
  ⚠️ `os.homedir()` **只调一次** —— `@/ledger/path.ts` 把 `env` 与 `homedir` 都做成入参正是为了这条。
  ⚠️ 版本号**逐字**读 `process.env.APP_VERSION`：`build.mjs` 的 esbuild `define` 替换的就是那段
  文本，写成 `{ ...process.env }["APP_VERSION"]` 就绕过了替换。
  ⚠️ **行数与列数同样重要**：全屏布局按 `rows` 分「结果区 / 输入区」，缺了它整个主区高度是 0，
  界面上只剩两个空框 —— 而那不是「屏太小」，是**根本没拿到屏有多高**。
- **零 `console`**：出口只有 `process.stderr.write`，且只在组合根（参数拒绝 / 非 TTY 拒绝 /
  Ink 的错误边界兜住的东西）。界面内的一切瞬时消息走输入区中间那一行。
- **台账坏 ≠ 空台账**：`readLedger` 抛 `LedgerError` 时**不 `holdLedger`**（内存里那份台账的写入口
  只有两个调用点：读成功与台账写落盘），另存 `ledgerError` 并把它显示在输入区中间那一行。
  ⚠️ 同理**不清掉**内存里上一份好的（那是操作者此刻唯一还能看见的那份端点清单，而本层每一次写都
  现读现写，故它不可能被拿去过覆盖磁盘）。
- **台账写一律现读现写**：`readLedger` / `writeLedger` 都是同步的，读-改-写之间没有 `await`，故
  不存在被别人插进来的窗口。少了「现读」这一步，刚在界面上加的那个目标会被内存里那份旧副本覆盖掉。
- **写入失败不吞、也不回滚**：`switchTo` 写失败仍把内存里的当前目标切过去，并把
  「没存进台账 / 关掉就没了」说进输入区。回滚会让「刚才那次操作」看起来没发生，而它确实发生了、
  只是没存下来。⚠️ 那之后**下一次重读会让磁盘赢**（`ledgerTick` 一动就读回真值）—— 那是**收敛**，
  不是回滚：回滚发生在动作当场，收敛发生在下一次有别的动作写它的时候。
- **`epoch` 只在动作时 +1**，绝不**在每次渲染或每次按键时** +1 —— 那会让每一个在途请求立刻过期。
  ⚠️ 本层现在**没有** `epoch` 状态（那是页面层的机制，页面删了）：命令是**串行**跑的
  （见下），「过期响应」这个形状本身已经不存在了。
- **命令排队、一条一条跑**（`app.tsx:pump`）：`Effect` 里有 `clear-log` 与 `ledger-changed` 两个会
  改动别的东西的动作，并发跑两次命令时一个 `clear-log` 会把另一条刚落地半秒的结果一起抹掉，
  而屏幕上没有任何东西解释它去哪了。串行化之后「按下回车的那一屏」与「结果贴上去的那一屏」永远同序。
- **探活只在本层发生，且只有一份结论**（`reprobe` 写 / `probes` 读，存的是**探活持有的值**而不是
  呈现档）：侧边栏那一列字形是它**唯一的**读者，而走**同一个**换算
  （`@/ui/theme.ts:connectionStateOf`）。⚠️ 两处各探各的，分叉出来的不是「多一次请求」，而是
  **同一屏上两句话**（「未知 / 还没探过」与「未连接」），且两处各自都没 bug。
  `tsc`、lint 与本包那几百条单测全都看不见它，只有真渲染看得见。
  - **两个触发点、一个实现**：当前目标变或挂载（那个 effect）与 `r` 命令（`Effect: reprobe`）。
    ⚠️ **不许为「按 r」再加一个计数**（曾有过这样一个计数，它让「按 r」这件事绕道 effect）：
    那是多一条「靠改状态让 effect 重跑」的暗道，而那条暗道迟早会长出「按 r 探的是不是当前那个
    目标」这种说不清的分支 —— 直接调同一个 `reprobe` 就没有这个问题。
  - ⚠️ **过期响应按 id 的序号作废**（`probeSeq` ref：每次调用自增，回来时序号仍匹配才写回），
    **不靠 `useEffect` 清理函数里的 `alive` 标志** —— 后者只在 effect 重跑时翻转，而 `reprobe`
    是普通回调（按键与副作用都调它），**没有清理时机**。不换守卫的后果是「切得快一点」或
    「连按两次 `r`」时旧结果盖掉新结果：屏幕上仍然自洽，**但那个自洽的结论是过期的**。
  - ⚠️ **「在飞」与「结果」同容器**：`probes` 是那**一个** `Map<id, ProbeSlot>`，值是
    `@/ui/theme.ts:ProbeSlot`（`ProbeResult | { pending: true }`），`undefined` 仍表示「还没探过」。
    **一个 id 一个值** ⇒ 侧边栏结构上不可能对它说两个词。⚠️ 在飞**不是**另立一个状态容器：
    第二个容器一出现，侧边栏就能再次对同一个目标说两个词。
  - `reprobe` **发请求前先写 `{ pending: true }`**（同一个 map 覆盖那一格），于是呈现侧读作
    `connecting`。⚠️ 理由：一个 `timeoutMs` 4000 的死目标在飞那 4 秒里必须与「从没试过」说
    **不同的词** —— 前者等一下就好，后者是一次从没开始的尝试，而说「未知」的话操作者分不出
    「还没开始」与「卡住了」。
  - ⚠️ **`probeTarget` 自己都兜不住时（`catch` 那一支）那一格整格删掉**（回到「还没探过」），
    而不是留着 `{ pending: true }`：那是本包自己有 bug 的路径，屏上此刻**没有任何事实** ——
    一句永远兑现不了的「连接中」是最坏的一种显示。
- **`client` 的身份由一个串决定**（`id` / `baseUrl` / `token` / `timeoutMs` 的 `JSON.stringify`），
  不是由 `Target` 那个对象决定：台账每重读一次就造出一批同内容的新对象，跟着对象走会让执行层
  在每一次动作之后都重发一遍。
- **退出必须先 `unmount()`**：`cli.tsx` 只设 `process.exitCode`，并在 `waitUntilExit()` resolve
  之后才设 —— `process.exit()` 会在 Ink 还没 show 光标、还没关 raw mode 时把进程切断，留下一个
  没有光标的终端，且退出后屏幕停在全屏界面上。⚠️ 收尾有**三条**到达路径（`finally` /
  `process.once("exit")` / `waitUntilExit`），三者共用**一个**幂等的 `finish()`。
- **一个控制面都没有时**：侧边栏只有一个会话项（第二行是「未选控制面」），主区出 logo 与
  引导语，而状态行左半说「台账里没有控制面」。⚠️ **logo 让位给输出**：判据是「当前会话**还没有任何
  输出**」—— 台账为空时唯一能敲的两条命令（`target add` 与 `help`）的输出正落在那里，严格按
  「没选中就永远出 logo」实现会让本工具唯一能教会用户怎么用的那条命令的输出**永远看不见**。
- **输出桶是每个会话一份**（不是「一个全局日志 + 一个全局当前目标」）：那样「切会话」就只等于
  换个名字，而「这个会话刚才那条命令跑在哪台机器上」答不出来 —— 而结果区里那些行**不显示**打给谁。

## 层不变量：本层**没有**「组合根必须知道谁在收字符」那一条

⚠️ 旧架构里有一条很重要的判据：「Ink 把每一个键交给**所有**活着的 `useInput`，所以页面开着输入框
时组合根的全局键会让路」。**它连同页面一起没了**：现在只有一个输入行，且它是**本层自己**的
`useState`，故本层**同时**是那个焦点的主人 —— 没有任何一个键是「内容」与「命令」两种意思。
⚠️ 别把它加回来：加回来的那一刻会多出一层「谁在收字符」的上报通道，而本层已经**天然**知道。

## 已知缺口（是「不变量」，不是「没来得及」）

- **`Ctrl+C` 之外没有第二条退出路径**，且本层不实现它（Ink 处理）。⚠️ 代价：一条**不发 Ctrl+C
  且不关 stdin** 的输入流会让用户只能用信号杀进程 —— 而那种终端本来就不可用。
- **窗口尺寸是一次快照**：本包不挂任何 `useWindowSize` 之外的监听（Ink 会重渲染，但
  `geometry()` 的入参是 props），故**改宽窗口后布局要重开一次**才更新。⚠️ 拉一个 resize 监听会多出
  「重排过程中鼠标坐标按旧矩形判」那一类竞态，而那比「改窗口要重开」贵。
- **输入行以 `/` 开头是**形状**不变量**：每一行命令都必须以它开头（`@/cmd/parse.ts:COMMAND_PREFIX`），
  而「带前缀的命令名写成什么样给人看」只有**一个**出口（`CommandSpec.path` = `/` + `name`）。
  ⚠️ **不许「宽容地」接受不带前缀的写法** —— 那会让这条不变量变成一句没有牙齿的话（两套写法都能跑，
  而其中一套会在下一版消失）。牙齿：`packages/tui/tests/parse.test.ts` 末尾那一组断言。
- **命令面板**开不开**只**看「输入行里有没有 `/`」，而高亮是**输入行的纯函数**（界面上没有
  「高亮在第几行」这个状态），`↑`/`↓` 走完之后**把那一行写进输入行**—— 于是「输入行上敲的是 A、
  面板高亮的是 B」在类型上不可能发生。⚠️ 面板**关**着时 `↑`/`↓` 才是切目标、滚轮才是滚结果区。
  ⚠️ 而「命令名那一段」的宽度判据**只有一处**（`@/cmd/palette.js:commandPathOf`，
  `commandHead` 与 `paletteFill` 共用它）：判据是「**表里有没有一条命令名以这一段开头**」，
  而**不是**「是不是被选中那条命令名的前缀」—— 后者只在**新名字更长**时成立，于是
  `/user add` 走到 `/user set` 时只吃掉 `user`，剩下的 ` add` 变成尾巴（一条命令里夹着一个形参，
  而 `parseLine` 不会因此报错）。⚠️ 同一个判据**跨空白**：`/user add ` 的命令名是 `user add`
  而不是 `user`，按空白截断会让高亮停在上一条命令上，屏上那个形状是「按了 `↓` 它不动」。
- **本目录零针对纯逻辑的单测**（`app.tsx` / `cli.tsx` 里可脱离 Ink 断言的东西只有输入行那几个
  纯函数与几何）：它们挂在 React 上，起一次真渲染比造一层「为覆盖率造出来的抽象」便宜 ——
  那层抽象会让「一屏上到底显示了什��」变成读不出来的东西。⚠️ 真正的验证在
  `tests/layout.test.ts`（假 TTY 真渲染）与 `tests/input.test.ts`（假 TTY + **真 Ink 输入通路**
  + 真 `App`：喂进去的鼠标报告一个字都不许进输入行）；本包末尾「人工验收」那一节是剩下的一半。
- **hover 是「指针在哪」，选中是「我选了哪一台」**：两个**不同的**状态、两个不同的通道
  （底色 vs 文字颜色），于是「选中的那一项恰好被指着」时两件事都还看得见。⚠️ hover 按 `id` 记而
  **不按下标**：台账每重读一次就是一个新数组，按下标存着的那个会在重读那一刻指着另一台。
  ⚠️ 且**只在真的换了一项时 `setState`**（同一个值原样返回 ⇒ React 跳过重渲染）：`?1003h` 开着
  是一秒几百条报告，而「手在侧边栏里划一下」屏上一个字都不该变。
- **输入行有**两道闸，少任何一道都不成立**：`isMouseReport`（认领终端协议报文）与
  `printableOnly`（剔 C0 与 `DEL`）。⚠️ 后者**单独挡不住鼠标报告** —— Ink 在把未解析的序列交给
  `useInput` 之前就把那个 ESC 拿掉了，于是报文到这里全可打印。⚠️ 前者也**不能**替代后者：
  它只认结构上就是报告的那些，粘贴进来的 `U+000D` 仍会进输入行并跟着 token 发出去（恒 401）。

## 重复：为什么同一段话在这里又有一份

`describe(err)` 与 `@/exec/run.ts:controlFailure` / `ledgerFailure` 是三份「把一次失败变成
一句话」的逻辑。这是被目录形状逼出来的（执行层是纯函数、不挂 React，而本组件没法被纯函数层
import —— 反向依赖会把执行层拖上 React）。⚠️ 三处都**不许**引用 token 的内容，也**不许**转述
非 `LedgerError` 的异常（那串字节可能带得出下层的凭据）。
