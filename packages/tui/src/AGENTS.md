# src/ — 控制面契约、请求形状、本地库与启动器（重构空白期）

⚠️ **重构期**：启动一侧已重建为 `cli.ts`（入口）→ `starter/`（建根 + 插件 + 预设）；**UI 在 `ink-ui/` 重建中**，状态层待定；`api/` `lib/` `config/` `db/` `service/` 照旧；`agents/` 已接上 `tools/`（注册表 + `shell` / `webfetch`）与 `mcp/`（MCP 加载器），`agent-loop` `prompt` `sessions` 待建。

⚠️ **`ctx` 上一个能力一个名字**（`cfg` / `db` / `dao` / `services` / `tools`），不开别名。⚠️ **`ctx.dao` 只带「有哪些行操作」，不带库** —— 库永远由调用方当第一个参数显式传（`ctx.db`，或事务回调里的 `tx`）。

⚠️ **日志只有 cordis 一个出处**：任何目录（`lib/` `config/` `db/` 这些不认 cordis 的层也一样）都不许 `console.*`，也不许自建 logger 实例。理由不是洁癖，是 `ctx.logger` 是**可拦截的服务**（`ctx.logger.exporter(...)` 能卡级别、转文件、接进 Ink），绕开它这些开关就全失效。裸 `console` 被 eslint `no-console` 挡死、**不许加 `eslint-disable` 绕过**。

- 档位就四个：`debug` / `info` / `warn` / `error`，**没有 `success`**。⚠️ 默认门槛是 `info`，`ctx.logger.debug(…)` 除非有人配 `level` 否则一条都不导出 —— 要紧的事别记在 `debug` 里。
- 第一个参数是 printf 风格格式串（`%s` `%d` `%o` …）。**报错直接把 `Error` 单独丢进去**（`ctx.logger.error(err)`）：自动打 stack，`cause` 与 `AggregateError` 会递归展开，不必自己拼 message。
- 前缀名字自动取当前 fiber（`hyphenate(fiber.name)`），不用自己写。
- 不认 cordis 的层（只有 `db/`）确实要把话递到终端时，**由调用方传回调进来**，见 `starter/` 那行的 `report`。

| 路径 | 答什么 |
|---|---|
| `api/` | 控制面 HTTP **契约 + 拨号**：一端点一函数，**唯一**那条 `axios.request` 住 `transport/send.ts`。⚠️ 地址与 token 是**函数参数**（`ManagerTarget`），没有「客户端对象」这一层 |
| `lib/` | 零 IO 纯函数层，深路径直引（无 barrel）：`request/{errors,http,transport}.ts` 请求那一圈三个叶子（⚠️ `api/` 只许引这三个、禁引 barrel——成环）；`model-id.ts` 模型键词汇（⚠️ 按**第一个** `/` 切，`model` 可含 `/`）；`obj-util.ts` 深遍历两件套 `deepFreeze` / `deepEqual`（只认 JSON 形状） |
| `config/` | 本地配置：装载（一节一个文件夹 = 默认值 + 校验，`loader.ts` 只分派 `database/` 与 `agents/`）→ 活配置 `ConfigStore`（`get` / `set` / `reload` / `onReload`，交出冻结快照）。⚠️ 坏 JSON / 认不得的项 = 启动失败；`set` 只改内存不写盘。⚠️ **`agents/` 一节现在只剩 `maxSteps`**：要起哪些 MCP 服务器住在 `mcps` 表里（读写走 `ctx.services.mcps`，见 `agents/` 行），**配置里不再有 `mcpServers`**——留着它就等于给同一批服务器留第二个出处，而服务器名要进工具名 `mcp__<id>__<工具>`，顶掉哪一台极难查。⚠️ 手上的 `config.json` 若还留着 `mcpServers` 会**启动失败**（`assertKeys` 认不得它）：这是刻意的，别为了迁就旧配置去放宽那条 |
| `db/` | 本地库**底座**：开 / 关库（`dialect.ts`，只有 sqlite 能开）、drizzle 表（`sqlite/schemas/`：`providers` 提供商 + `models` 模型 + `mcps` MCP 服务器（stdio / http / sse 三档，`mcps_disabled_id_idx` 索引 = 启动时取没 `disabled` 的那批）+ 原有的会话/消息三表）、运行期建表（`sqlite/init.ts`：空库的 `CREATE TABLE IF NOT EXISTS` 镜像 + **结构同步的入口** `ensureSchema`）+ **结构同步**（`sqlite/upgrade/` 一个文件夹五件事：`diff.ts` 只读比对（`missing` / `extra` / `changed` 三档列差异 + 索引差异）、`ddl.ts` 把 drizzle 声明翻译成 SQL、`rebuild.ts` 重建表（改类型或 NOT NULL 时 SQLite 没有 `ALTER COLUMN`，事务里搬数据）、`sync.ts` 编排五步并记账、`index.ts` 出口。⚠️ **破坏性动作没有开关，删列是自动的**：schema 里少一列，下次开库那列的数据就没了（靠插件逐条打日志让人看得见，而不是靠拦着不做）；⚠️ **「多一列」与「改了列名」分不开**，只按「多了就删」处理 ⇒ **改列名要走重命名，别靠删了再加**；⚠️ 重建表**一张表一次**（只搬声明里的列 ⇒ 多余的列当场被丢弃，日志会点名丢了哪些）；⚠️ `sync.ts` 里的**五步顺序不能换**（重建表会把旧索引一起没掉 ⇒ 补索引只能排在它后面；删列前必须先拆依赖它的索引）；⚠️ 重建表时「收紧成 NOT NULL 的列」用 `coalesce(列, 默认值)` 搬（默认值只在不写该列时生效，直接搬 NULL 会炸），**没有默认值的必填列**动手前先查 NULL 并报错；⚠️ `DEFAULT` 不参与差异判定（库里是 SQLite 记的字面文本）；⚠️ 主键列不比 `NOT NULL`（`text PRIMARY KEY` 的 pragma `notnull` 是 0）；⚠️ 标识符不走 drizzle `sql` 模板（会被参数化成 `?`）；⚠️ 运行期**不应用** git 里 `drizzle/sqlite/` 各迁移目录的 SQL —— 那是「变更是什么」的留档，唯一需要人照着它手工处理的是重命名这类分不清的变更；⚠️ 索引名只有 drizzle schema 这一个出处，`init.ts` 的镜像里刻意不写索引；⚠️ `db/` 层不认识 cordis，也不打印 —— 事件与人话都在 `starter/plugins/db/`）、**DAO（`dao/`：各表原子 CRUD，无事务；⚠️ **每个函数的第一个参数是库句柄或事务代理，不是「绑好的仓储」** —— 事务里要传 `tx`，所以闭包持有 db 的写法一开始就不成立；`mcps` 那份没有跨表编排可做，所以**不引入事务**）、行映射与共享校验**（`read.ts`：`partFromRow` 仍是 `message_parts` 的行 → DTO，`requiredText`/`badContentError` 供 `service/` 共享写侧校验，provider/models 走 DTO（`@/db/dto/provider.js` / `model.js`），出入参即 `Provider` / `Model`（drizzle $inferSelect 行类型，派生 `NewProvider` / `ProviderPatch` / `NewModel`）、⚠️ **`mcps` 那张表的形状判据全部收在 `read.ts` 的 `mcpConfigFromRow` 一个函数里**（`transport` 决定哪几列必填、哪几列必须为空；表上刻意没有 CHECK —— 重建表复现不了它，差异比对也只比类型与 NOT NULL），⚠️ **「草稿 / patch 怎么变成与驱动写下的同形」也住在这儿**（`mcpNewRowFromDraft` 补 `NULL` 与列缺省、`mcpDefinedPatch` 剔掉显式的 `undefined`）—— 写面要拿**候选行**去过同一道闸，而闸读的必须是与表同形的那一行（`undefined` 不是 `NULL`，直接送进去会把「没写 url」判成「写了 url」）；两个调用方是 `db/dao/mcps.js`（谁写库都调它，免得交回半截对象）与 `@/agents/mcp/manager.js`（落库**前**拿候选行过闸）；连接配置那份形状在 `@/db/dto/mcp.js`（`MCP_TRANSPORTS` 闭合集 + `McpConnectionConfig`，是 `@ai-sdk/mcp` 两个传输配置的去形，⚠️ **不带 OAuth**：那是个带方法的对象，一行装不下而 TUI 也没有浏览器承接回调）、两档驱动（内置 `node:sqlite` 优先，退 wasm）；**两档都默认不开 WAL（内置档去掉 `PRAGMA journal_mode = WAL`），统一使用删除档（journal_mode = DELETE），保证库文件在任意 Node 版本间可互换，否则 Node 22.13+ 的内置档创建的 WAL 库文件，Node < 22.13 的 WASM 降级档打不开；WASM 档开库失败且识别出文件是 WAL 模式时，会备份旧库（`<path>.wal-journal-incompatible-bak`）并重建** |
| `service/` | 业务**服务层**（类）：`SessionsService` / `MessagesService` / `ProvidersService` / `ModelsService` / `McpsService`，**构造收 `Context`**，行操作走 `ctx.dao.*`、库句柄走 `ctx.db`；由 `starter/plugins/services` 挂到 `ctx.services.sessions` / `messages` / `providers` / `models` / `mcps` 上。编排跨表**事务**（`deleteProvider` 级联删模型 / `deleteSession` 级联删消息与段 / `appendMessage` 建消息 + 推进 `updatedAt`）；出入参走 DTO（`@/db/dto/`），读侧坏内容闸由 `read.ts` 兜底。⚠️ **不 import DAO**（eslint 红线，理由见 `plugins/` 行）：`ctx.dao` 只带「有哪些行操作」，**不带库**，所以每个 DAO 调用的第一个参数永远是 `this.ctx.db`（普通路径）或事务回调里的 `tx`（级联删 / 追加消息）—— 同一组调用在事务内外长一个样。⚠️ 事务内部只调 DAO 的原子行操作，不自己写 SQL（原 `messages.ts` 那条查会话存在性的裸 `tx.select(...)` 已收进 `dao.sessions.existsSessionRow`）。⚠️ **`McpsService` 只管数据**：七条方法逐条转发给 `ctx.dao.mcps`，写成功发一条 `mcp.data.changed`，**一条 MCP 的规矩都没有**（服务器名的尺子在 `@/agents/mcp/naming.js`、形状闸在 `read.ts` 的 `mcpConfigFromRow`、「这一行能不能起起来」全在 `@/agents/mcp/`）——⚠️ **由此 `service/` 不 import `@/agents/`**：业务服务层在 `agents/` **下层**，反过来引上层就是分层反了（这条没写进 lint 红线，得自己盯）。⚠️ 读侧**不过任何闸**（一台坏行照样读得出来），那台起不来是在对表时落成 `ctx.mcp.list()` 里的 `failed`；⚠️ 写侧**也不当场拒**半截行，那道「写不进一条读出来会被拒的行」的闸挪到了 `ctx.mcp`（`manager.ts` 落库**前**拿候选行过闸）⇒ 走 `ctx.mcp` 仍当场拒，绕过它直接写库的半截行由 `failed` 那条降级路径接住；⚠️ **`mcps` 是唯一会发事件的业务服务**：载荷只给「哪一行、怎么改的」，**不发行本身**（行会变，监听者自己重读），读方法一条都不发；⚠️ 事件刻意**不是**「开始 / 结束 / failed」那三段（写库是同步的一条 SQL，调用方拿到返回值时它已经完成了），⚠️ **监听器抛的错在这一步兜住**（数据已落库，把错冒出去会让调用方以为失败而重试一次，那才是真损坏） |
| `agents/` | **agent 的那一圈**（工具 + MCP + 循环）：`tools/` 工具注册表（`index.ts` 造工具的 `defineTool` + 登记的 `registerTool`，**模块级单例 `AGENT_TOOLS`**；⚠️ 重名 / 空名 / 带空白 / 说明为空都**当场抛**，那是装载期校验——跑起来才发现工具不对时，循环那一轮说的话已经没了；⚠️ `registerShellTool` 就是**把 shell 交出去**，没有白名单没有确认）；`mcp/` **这一圈整体都在本层**（`agent-loop` `prompt` `sessions` 待建），按「一台 → 一批」两半各拆几份，每份的理由在它自己文件头：`naming.ts` 命名规则（**零依赖**，`mcps.id` 与工具名的**唯一**出处）→ `transport.ts` 三档配置到 SDK 的两条路（stdio 的 `stderr: "pipe"` **写死**，`args` / `env` 各拷一份）→ `stderr.ts` 子进程 stderr 那一圈 + 失败消息的统一形状 → `connection.ts` 连一台（`initialize` 与 `tools/list` 两道时限闸）→ `session-tools.ts` 把一台给的工具搬进 `ctx.tools`（登记 / 跳过 / 补说明）→ `session.ts` 一台的活会话（起 → 登记 → 收）→ `status.ts` 一台的两个形状（运行期 `McpEntry` / 对外 `McpServerStatus`，五档状态）→ `plan.ts` 对表的**纯判定**（零 IO，不碰 ctx）→ `manager.ts` **那个类** `McpManager`（表 + 串行队列 + 起关重开对表 + 卸载收尾，`ctx.mcp` 的实现）。⚠️ **本层认 cordis**（与 `service/` 同列）：MCP 天生是带副作用的装配单元（起进程、读 stderr、登记），硬拗成零 cordis 纯函数只会逼出一堆 `report` 回调穿线。⚠️ **这一圈的状态只住在 `manager.ts` 的 `entries` 一处**，且⚠️ **它不缓存配置**：真值是 `mcps` 那一行，运行期只记一个 `rowStamp`（那一行的 `updatedAt`）用来判「改过没有」——存一份配置对象就是第二份会过期的真值。⚠️ **`mcps` 表只有 `ctx.services.mcps` 写**（它只搬数据 + 喊事件，一条 MCP 规矩都没有），本层**读**它（`manager.ts` 里不碰 DAO、不写 SQL）并**判断那一行能不能起**——⚠️ **闸在 `agents/` 这边，不在 `service/` 那边**：`manager.ts` 落库**前**拿候选行过形状闸（写不进一条读出来会被拒的行）、对表时逐台过（一台坏行只让那一台落 `failed`），两条都调 `db/read.js` 的 `mcpConfigFromRow` 那一个函数。⚠️ **MCP 的「子线程」是子进程**：stdio 的 JSON-RPC 走子进程 stdin/stdout，`worker_threads` 接不了这一层 |
| `plugins/` | **插件**：`starter` 树的插件**一插件一文件夹、代码写在该文件夹的 `index`**（`config/` / **`db/`** / `dao/` / `services/` / `tools/` / `mcp/` / `ui/`…），提供 `ctx` 服务与事件、挂载副作用；事件/服务的类型声明随提供者写在各自 `index` 里（`declare module "cordis"` 必须在提供者的 `index`）。本档的 `defaultPreset` 负责按顺序 `await ctx.plugin(...)` 装上它们，⚠️ **引用一律显式写全 `/index.js`**（`../plugins/mcp/index.js`）——不赌解析器对目录 index 的支持。⚠️ → 才 `ctx.provide("db")`）、`daoPlugin`（行操作目录，**不带库**）、`servicesPlugin`（业务服务）、`configPlugin`（`ctx.cfg`）、`toolsPlugin`（`ctx.tools`）、`mcpPlugin`（`ctx.mcp`，**持有服务器表**）。⚠️ **`dbPlugin` 是本地库的闸门**：`inject: ["cfg"]` → 开库 → 比对差异 + 迁移（补列 / 补索引 / 重建表 / 删索引 / 删列，全自动、没有授权开关）→ 广播 `db.synced`（结构化的差异 / 已做）→ 才 `ctx.provide("db")`；业务插件（如 `services`）一律 `inject: ["db"]`。⚠️ **闸门是结构性的、不是纪律**：全应用只有 `dbPlugin` 一处 provide 库，注不到就拿不到，「绕过闸门」这个错误形状不存在。⚠️ 开库或同步失败 = 本插件装载失败 = 启动失败（预设 await 了它），闸门不开 ⇒ 一个业务插件都不动。⚠️ `daoPlugin` **不 inject 任何东西**：行操作目录无状态、没有生死，同步没过的那段时间谁都拿不到 `ctx.db`，自然也调不动它。⚠️ 挂载点**必须**在 `starter/`：类型声明一旦落进 `db/dao/*.ts`，`db/` 那层「不认 cordis 的叶子」就作废了。⚠️ **五个业务服务不 extends Cordis 的 `Service`**：`Service` 构造会把自己 `provide` 上去，与 `ctx.services.*` 撞成两份真值；它们要的「fiber 卸载即撤销」由 `ctx.provide` 已经给了。⚠️ **`mcpPlugin` 排最后、`inject: ["db","services","tools"]`**（⚠️ **不再注入 `cfg`**：这一圈的真值是本地库而不是配置文件，两处都写就出两份真值）：`db` 是闸门、`services` 是那张表的唯一门面、`tools` 是登记口（MCP 的工具经它登记，注不到就装不上）。⚠️ **本目录只剩装配**（`index.ts` 一份）：声明服务与事件、`new McpManager`、`provide`、挂一个 effect —— ⚠️ 订阅 `mcp.data.changed` 与装载时那次对表**收在同一个 effect**（卸载时多个 effect 是**并发**执行的，分成两个就可能「监听器还活着、表已经收了」）。⚠️ 它的管理动作 `create` / `update` / `setDisabled` / `delete` / `restart` **改数据与改运行期是同一个动作**（经 `ctx.services.mcps` 落库后立刻对表，返回时运行期已经是新的，不必再手动 `reload`），`create` 的入参**只有 `id` 与 `transport` 必填**且时间戳由管理器填（`dao/` 与 `service/` 都不读时钟）；⚠️ 这些动作与 `reload` **全部串行化**在一条 promise 队列上（各自 await 一台服务器的起落，可达几十秒；不串行则两个并发 `restart` 各开一个会话 ⇒ 前一个的连接与工具全泄漏，队列用 `then(work, work)` 以免前一次失败把插件堵死）；⚠️ 发事件的调用点**一律兜住监听器抛的错**（`ctx.emit` 不隔离，而发事件时状态刚改到一半，一个抛错的监听器会把那一台永远留在
