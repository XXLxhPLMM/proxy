# src/ — 控制面契约、请求形状、本地库与启动器（重构空白期）

⚠️ **重构期**：启动一侧已重建为 `cli.ts`（入口）→ `starter/`（建根 + 插件 + 预设）；**UI 在 `ink-ui/` 重建中**，状态层待定；`api/` `lib/` `config/` `db/` `service/` 照旧。

⚠️ **`ctx` 上一个能力一个名字**（`cfg` / `db` / `dao` / `services` / `tools`），不开别名。⚠️ **`ctx.dao` 只带「有哪些行操作」，不带库** —— 库永远由调用方当第一个参数显式传（`ctx.db`，或事务回调里的 `tx`）。

⚠️ **日志只有 cordis 一个出处**：任何目录（`lib/` `config/` `db/` 这些不认 cordis 的层也一样）都不许 `console.*`，也不许自建 logger 实例。理由不是洁癖，是 `ctx.logger` 是**可拦截的服务**（`ctx.logger.exporter(...)` 能卡级别、转文件、接进 Ink），绕开它这些开关就全失效。裸 `console` 被 eslint `no-console` 挡死、**不许加 `eslint-disable` 绕过**。

- 档位就四个：`debug` / `info` / `warn` / `error`，**没有 `success`**。⚠️ 默认门槛是 `info`，`ctx.logger.debug(…)` 除非有人配 `level` 否则一条都不导出 —— 要紧的事别记在 `debug` 里。
- 第一个参数是 printf 风格格式串（`%s` `%d` `%o` …）。**报错直接把 `Error` 单独丢进去**（`ctx.logger.error(err)`）：自动打 stack，`cause` 与 `AggregateError` 会递归展开，不必自己拼 message。
- 前缀名字自动取当前 fiber（`hyphenate(fiber.name)`），不用自己写。
- 不认 cordis 的层（只有 `db/`）确实要把话递到终端时，**由调用方传回调进来**，见 `starter/` 那行的 `report`。

| `service/` | 业务**服务层**（类）：`SessionsService` / `MessagesService` / `ProvidersService` / `ModelsService`，**构造收 `Context`**，行操作走 `ctx.dao.*`、库句柄走 `ctx.db`；由 `starter/plugins/services` 挂到 `ctx.services.sessions` / `messages` / `providers` / `models` 上。编排跨表**事务**（`deleteProvider` 级联删模型 / `deleteSession` 级联删消息与段 / `appendMessage` 建消息 + 推进 `updatedAt`）；出入参走 DTO（`@/db/dto/`），读侧坏内容闸由 `read.ts` 兜底。⚠️ **不 import DAO**（eslint 红线，理由见 `plugins/` 行）：`ctx.dao` 只带「有哪些行操作」，**不带库**，所以每个 DAO 调用的第一个参数永远是 `this.ctx.db`（普通路径）或事务回调里的 `tx`（级联删 / 追加消息）—— 同一组调用在事务内外长一个样。⚠️ 事务内部只调 DAO 的原子行操作，不自己写 SQL（原 `messages.ts` 那条查会话存在性的裸 `tx.select(...)` 已收进 `dao.sessions.existsSessionRow`） |

## 改坏会红在哪

本包无单元测，依赖这三条：`pnpm lint`（语法/死代码 **+ 分层红线**）→ `pnpm typecheck`（跨层调用）→ `pnpm build`（产物可产出）。`lint` 现在**机械强制**两条不变量（`.eslintrc.cjs`）：① `db/` `lib/` `config/` `api/` 禁 import `cordis`；② `service/` 禁 import `@/db/index.js` 与 `@/db/dao*`。⚠️ override **不合并同名规则的 options**（后者整体替换前者），所以同一个 `no-restricted-imports` 的多条 `paths` 必须写在**同一个** override 里，拆开会静默丢掉一条。schema 变动另用 `pnpm exec drizzle-kit check`（`Everything's fine` = 无漂移）与 `pnpm exec drizzle-kit generate`（新迁移进 git；⚠️ 本仓的 `drizzle/sqlite/` 没有 `meta/_journal.json`，实测 `generate` 是纯加法、`check` 不删文件）。⚠️ **结构同步与闸门没有测试兜底**（当前阶段不新建 `tests/`），改它得手工对拍：造几个库副本（少列的 / 多列的 / 形状变的 / 别人建的），跑 `ensureSchema` 看 `applied`、再跑一次验幂等；闸门则 headless 挂 `config` + `dao` + `db` + `services`，验「没 `ctx.db` 时 `ctx.services` 拿不到」「开库/同步失败 ⇒ 装载失败且闸门不开」「同步失败仍发 `db.closed`（关库 effect 早于 `ensureSchema` 注册，不漏库）」。探针的三个坑：临时家目录用 `USERPROFILE` 隔开、**各块共用同一个家目录时后一块会读到前一块留下的库文件**（写坏了要清干净）；esbuild 除了 `nodePaths` 还得照 `build.mjs` 第 3 点把 `node-sqlite3-wasm.wasm` 复制到产物旁边，否则降级档加载期就炸；**判断插件装上没有只能看服务在不在**，`await ctx.plugin(x)` 对被 `inject` 挡住的 fiber 会立刻 resolve。探针脚本放临时目录、跑完即删。⚠️ `service/` 的类方法名改了 ⇒ `typecheck` 报 property 不存在；删 `src/service/` 任一文件 ⇒ `starter/plugins/services.ts` 报 import 错误；删 `dao/` 任一导出 ⇒ `ctx.dao` 的类型缺成员 ⇒ `typecheck` 报错。
