# tests/input/ — 假 TTY 真渲染：从屏上那一帧的字节读事实

本文件夹的档全部走**同一次真挂载**（`_shared.ts` 的 `mount`：假 TTY + 真 `App` + 真 `MouseSource` + 真 Ink），
然后**只从屏上那一帧的原始字节**判。它不是 `tests/mouse/` 那些纯函数断言的重复：那些档验的是
「`parseSgr` 认得认得」，而本文件夹验的是**两个消费者之间**发生的事 —— 纯函数档看不见它。

## 那一对消费者（这一整族档存在的理由）

同一份 stdin 字节被广播给两处：

- `@/services/terminal/mouse.ts` 的 `createMouseSource` —— 按 `parseSgr` 认出鼠标报告，派发成事件；
- Ink 自己的 `useInput` —— 把**未解析**的转义序列当文本交给 `AppState.tsx`，**并在交给之前顺手砍掉那个 ESC**
  （`ink/build/hooks/use-input.js`：`if (input.startsWith('\u001B')) input = input.slice(1)`）。

于是 `ESC[<35;64;32M` 到达输入层时是 `[<35;64;32M`：**一串全是可打印字符**，而
`AppState.tsx:printableOnly` 那道 C0 的闸在这里**已经失效**（唯一的 C0 字节被 Ink 拿走了）。
结果是输入行里逐字长出协议报文 —— `?1003h` 开着时移动一次鼠标就是几十行那种。

## 判据纪律

- **判据直接取屏幕上那一帧的原始字节**，不去 ANSI：只断言「`[<` 一个字都不许出现」与「`❯ typed` 必须在」
  两件事，而任何一条 Ink 自己写出的转义序列里都不会含 `[<`（它只写 `?2026h` / `2J` / `3J` / `H` / `?25l` /
  `?1000h` 那一族）。故不必为某一档抄一份 `stripAnsi` —— 而抄一份正是两份判据的开端（真要剥就去
  `_shared.ts` 里那一份）。
- ⚠️ **反向自检**：每一条断言都配一条**正向对照**（真敲的字必须出现在输入行上 / 那把「一个键位写了多少字节」
  的尺必须是真的）。少了它，「输入行是空的」会因「Ink 根本没渲染」而绿 —— 而那恰恰是这一类界面最可能的
  失败形态。⚠️ 而**正向对照与它要护的那条断言必须在同一个 `it` 里**：分开放两条时谁删掉哪一条，
  剩下的那条都是纯装饰（实测「喂 `Ctrl+C` ⇒ 屏上零变化」把整个 `useInput` 挂空照样绿）。
- ⚠️ **「屏上零变化」那一族不许挂空判据**：它只说「没动」，而一个**什么都不做的**实现也满足它。
  正向对照要落在「**这个 handler 真的改变过屏面**」上，不是「源码里有某个分支」（那种恒真）。
- ⚠️ **坐标一律从 `@/lib/geometry` 算**，不写死屏幕行号：写死的后果是「几何一改、点就点空了而断言照旧绿」
  （那种假绿最难发现，它看起来一直是对的）。几何是 **0-based**、SGR 上报是 **1-based**，**两个偏移都得有**。
- ⚠️ **侧边栏第一项之下恒有 `SIDEBAR_TOP_PAD_ROWS` 行留白**（它在**第一项之上**，故第一项落在第 1 行）：
  ⚠️ `_shared.ts:sidebarGeo` 的文档注释里仍写着「第一项就落在第 0 行（顶部不留白）」，而**那一档的判据
  没有跟着腐烂** —— 它们全部从 `geometry()` 现取期望值、不写死行号，故那句话烂掉的地方**只有注释**。
  ⚠️ 这正是上面那条纪律的兑现：**把偏移交给几何层之后，「几何改了一行」与「断言忘了改」不再耦合**，
  而读到那句错字的人会以为可以省掉那个偏移 —— 故以本条为准。
- ⚠️ **「侧边栏上有没有它」这类判据必须按列切**（`sidebarOf`）：瞬时消息与命令回显都落在主区，而它们逐字包含
  会话名 —— 不切列的话「藏起来了」与「屏上还有那个名字」在判据上分不开（实测踩过一次）。
- ⚠️ **「输入行上有没有它」同理要按区域切**（`inputOf`），而这条比上面那条更隐蔽：提示符 `❯ ` **两处都有**
  （输入区那一枚与结果区里那一格用户消息），且敲进去的那一串在**结果区**里还会逐字再出现一次 ⇒ 在整帧上判
  「输入行空了」与「屏上还有那一格回显」**完全分不开**（实测：「`↓` 清空输入行」那一档在整帧上恒绿）。
  ⚠️ 切的时候**按显示列**而不是字符下标 —— 那一格前面就有一枚两列宽的 `❯ `。
- ⚠️ **`boldRuns` 读的是剥 ANSI 之前的那一帧**：它认的就是那些转义序列，而剥完之后它恒答「一段都没有」
  （实测踩过一次）。⚠️ 而它答的是「**哪几段是加粗的**」而不是「有没有加粗」—— 插入符那一格也是加粗的。
- ⚠️ **不许拿一行正则去读带 ESC 的帧**：`no-control-regex` 是本包的纪律，而给测试档开一条 `eslint-disable`
  等于让这条纪律从此不再被看见。故 `stripAnsi` / `boldRuns` / `bgBefore` 三处**逐字符扫**。
- ⚠️ **每一档要么换挂载，要么把键喂完再读**：`finish()` 会 `unmount()`，之后喂的键**一个都不进应用**，而
  非交互档只在 `unmount()` 那一刻写一帧 —— 故「重开」这件事只能靠另一次挂载造出来。
- ⚠️ **「按了某个键」造不出「队列里还压着东西」**：`feed` 每两个 chunk 之间都 `await settle`（≥40ms），
  而一条本地命令几十毫秒就回来了 ⇒ 「还有东西在飞」必须**捏住 fetch**（`exit.test.ts:holdUsers`）才造得出来。
- ⚠️ **改一次键之后**要**等它真的排出一帧**（`feedRendered`）：`feed` 等的是「输出不再变」，而
  **非交互档中途一个字都不写** ⇒ 它退化成 40ms 的固定下限；加上 Ink 把渲染**节流到 30fps**
  （`maxFps` 默认 30 ⇒ 34ms），「改名框」那类要过「命令落地 → 改状态 → 几何重算」的键在并发下
  抢在重排之前（实测那一档**整套里偶发红、单跑 3 次全绿**）。⚠️ **闪的测试比没有测试更坏** ——
  它训练出「重跑一次就好」的习惯，而下一次它闪在真回归上就没人当真。
  ⚠️ `feedRendered` 的判据是 **Ink 自己报的帧数**（`render()` 那个 `onRender`）而**不是**
  「屏上出现了某句话」—— 后者等的就是要断言的那个字，于是断言永不可能红。
  ⚠️ 而反过来：**不能靠「一次 push 塞两个键」来赶时间** —— Ink 的 `input-parser.js:push` 对**没有 ESC 的
  那一整段**只产**一个**事件，于是 `/exit` + `Enter` + `/new` + `Enter` 连着进去会被当成**一串可打印文本**
  （`❯ /exit/new`），回车根本不会被识别。**只有 `\x7f` / `\x08` 被单独切开**。

## ⚠️ 全文件夹**开着 `FORCE_COLOR`**（三处逼出来的，缺一不可）

- hover 那几条要比**底色**，而无色终端里底色根本不存在 → 判据在无色档上恒红。
- ⚠️ 而开着它之后**只有「片段内部被切开」的那些判据**需要剥 ANSI（只有 `palette.test.ts` 的幽灵文本那一处：
  插入符那一格会把 `tatus` 前面的串切开）。片段**之间**多出来的转义序列不影响 `toContain`。
- 顺带：**双刃**。它让这一族档第一次能端到端验「`move` 报告 → hover 状态 → 那一项换底色」这条链路，
  而此前 hover 只在 `tests/layout/selection.test.ts` 里以 props 的形式验过（渲染那半）。

## 顺带钉住的那件事：移动鼠标**不该引起任何重绘**

⚠️ 这不是「顺手发现的」—— 认领掉协议报文之后 `useInput` 一个状态都不改，于是 React 不重渲染、Ink 不排帧，
50 条移动报告往终端写 **0 字节**（实测 win32 / 100×28；一个真键位是 3.4 KB 的一次整帧）。
⚠️ 修好之前那 50 条报告是 50 次整帧重画，而本包的布局恒等于 `rows` 高 ⇒ 每帧都是 fullscreen ⇒ win32 上
Ink 走 `clearTerminal` + 整帧（实测约 5.9 KB/帧）—— 那才是「一动鼠标就卡」的真凶。
⚠️ 那几条判据**必须用默认的 interactive 模式**：非 interactive 模式下一帧都不排，量出来恒为 0（假绿）。

⚠️ 上面那条判据**仍然成立**：hover 只在**换了一项**时 `setState`（同一个值原样返回 ⇒ React 跳过重渲染），
而 `?1003h` 开着时一秒几百条报告绝大多数落在同一项上。

## 呈现层那一族：零外部组件库

⚠️ **呈现层的词汇全部在 `src/components/` 与 `src/features/`**，依赖面只有 `ink` / `react` / `string-width`。
判据是**依赖面**（读 `package.json` 那个文件本身），不是「某个 import」—— 装了而没引与引了而没装是两种事，
而只有前者能在引入之前就红。逐个组件的否决理由归 `packages/tui/AGENTS.md`「零外部组件库」那一节。

## ⚠️ 本文件夹**不证明鼠标那侧能用**

它证明的是「同一份字节**没有**被当成文本」。「终端真的会发 SGR 报告」「点击落点对不对」仍需一次真终端人工
验收（见 `packages/tui/AGENTS.md` 末尾那一节）。

## 变异实测记录

跑法：先跑一遍基线档并断言它**全绿**（spawn 失败会长成「全部变异都红」那种假象，实测踩过一次），再逐条改源码
→ 跑对应那一档 → 复原 → 记下「哪些判据转红」。下面每一条都实测过。

- `move` 那个 case 改名成永不匹配的值 → 「指到侧边栏那一项」转红。
- hover **不跟着指针离开而清掉**（`now === null` 时原样返回旧值）→「划到主区回到列那一条」转红。
- 「改窗口大小」那一族：把 `@/hooks/useTerminalSize.ts` 的 `onResize` 改成开头就 `return`（当那个事件没来）⇒
  「拉宽拉高」与「拉窄到侧边栏画不出来」两条**都**转红（锚点分别从「120 列 / 第 35 行」退回「100 列 / 第 23 行」
  与从「第 1 列」退回「第 23 列」）。⚠️ 而同族那一条「报上来一个**不可用**的尺寸」在这次变异下**照旧绿** ——
  它判的是另一条分支，单独跑它什么也证明不了（这是它必须与上面那两条同属一档的原因）。
- 再把 `usable(stdout.columns) ?? initial.columns` 改成 `stdout.columns`（去掉那份兜底）⇒ **只有**「不可用的尺寸
  回到快照」那一条转红（锚点的行号从 23 变成 21：几何被 `undefined` 毁了）。
- ⚠️ hover 那三条断言里最要紧的是**探测器**：第一版写成「剥掉 ANSI 之后找 `48;2;`」，于是它永远是 `null`，
  而症状是「hover 从来没生效过」—— 与「探测器坏了」**长得一样**。故 `bgBefore` 在**没剥**的那一行上扫
  （只有「找行」那一步用 `stripAnsi`）。

### 退出那一族（E1–E5）

⚠️ 这一组与上面两组分开是因为它红的判据**一个都不与上面重叠**：上面管「键落在哪一层」，
而这一组管「唯一那扇门退不退得成」与「**刻意什么都不做**的那一键」。

（「点右上角点不动」）与一个恒 `true` 的（「改名框开着时点右上角把窗关了」）都查不出来 ——
而这两个症状在屏上都只是一片空白。故判据必须**正反两面各一条**。

⚠️ **E1 是本组最要紧的一条**：那一族此前**一条断言都没有**，而仓库里有一句文档说过
「`Ctrl+C` 到不了这一层（Ink 自己先处理了它）」—— 与 `exitOnCtrlC: false` **矛盾**，骗过人一次。
故判据是**喂键之后屏上零变化**，而**不是**「源码里没有 `Ctrl+C` 分支」：那种判据恒真
（把它删掉之前它一直是绿的，而删掉之后它也一直是绿的）。

### 逮到过的**原本恒绿**的判据

- ⚠️ **M7**：改之前那条只断言「屏上有『未选控制面』」，而**切回会话 1 之后会话 2 的第二行照样是那一句** ——
  于是「窗口吞掉了点击」与「点击切了过去」在屏上完全一样。已改成断言**加粗的那一项**（会话 2 仍被选中）。
- 同类形状在侧边栏那一列上还有一处：**项与项之间那一行**曾经被当过「点会话 1」，而那一档现在带一条
  **反向对照**（点那一行 vs 点它下面那一行，两者必须不同）。
- ⚠️ **T11 之前那一版**：两级 `Esc` 的第一条断言写的是 `not.toContain("✎ " + 改完的名字)`，而框里的插入符起手
  落在名字**末尾** —— 改完是「✎ 会话 1改名了」，于是**框开着时也照样通过**（恒真）。已改成锚提示符本身
  （`not.toContain("✎")`）**并加一条反向自检**：同一个 `✎` 锚点在框开着时确实钉得住。
  ⚠️ 判据形状与根 `AGENTS.md`「写护栏时」第③条同源：**负向断言的锚必须是一个今天仍然会变的东西**。
