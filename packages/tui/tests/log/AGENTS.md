# tests/log/ — `@/lib/log`（对话模型 + 行模型）的纯函数断言

| 档 | 内容 | 判据的对象 |
| --- | --- | --- |
| `layout.test.ts` | ①折行按**显示宽度** ②截断必须留标记 ③滚动位置恒以行为单位 ④行数与高度自洽 | 摊平出来的**行** |
| `entry.test.ts` | ⑤环形缓冲丢掉的最早一条报得出来 ⑥凭据掩码定长 | `entries` 那个**数组**与每条上的字段（零 `flatten` 调用） |
| `turn.test.ts` | ⑦`Turn` 的六个变体各一例，判据按 `kind` 与**色档** | **变体清单**本身 |
| `rows.test.ts` | ⑨`user` 那一档行的**折行形状**：**每一段**都带 `kind:"user"`、不标截断 | 那一档行的**逐段 `kind` / `clipped`** |
| `codec.test.ts` | ⑧落盘那一格 ⇄ `Turn[]` 的往返**逐字节**、不像一个 `Turn` 就抛 | 那段 **JSON 字节** |

**锁什么**：①换行按**显示宽度**（不是字符数）；②表与键值对**不换行**、按宽度截断且**必须留省略标记**；
③滚动位置**永远以行为单位**且夹在「能滚到底也能滚到顶」之间；④摊平后的行数与高度**永远自洽**；
⑤环形缓冲丢掉的最早一条**必须能报出来**（否则操作者以为历史是完整的）；⑥掩码**定长**；
⑦六个变体各摊出一行，判据**不靠字符串嗅探**（⚠️ 而 `user` 那一档**独占** `kind:"user"` ——
「我敲的」与「要执行的那条」屏上必须分得开）；⑧`messages.turns` 那一格的编解码**逐字节幂等**，
而**不像一个 `Turn` 的字节即拒**（不降级、不猜）；⑨折行的**每一段**都带 `user` 那一档
（气泡按逐行的 `kind` 分派）。

## 为什么拆掉哪一处会红

- `wrap` 里的 `stringWidth` 换成 `ch.length` → 「`a中b` 宽 2」那组给出 2 行而不是 3 行。
  ⚠️ **纯 ASCII 的用例对两种度量都成立**，所以每条折行判据都必须带 CJK 行，否则那条护栏恒绿。
- 把 `table` / `kv` 也放进 `WRAPPABLE` → 「表不换行」那组红（一张被软换行撕开列对齐的表，
  在真终端里比被截短的表更难读，而症状是「表格右边参差不齐」）。
- `clampTop` 去掉「装得下就归 0」那一支 → 「内容装得下时归 0」那组红（死滚动条）。
- `clip` 不留 `…` → 「截断必须留标记」那组红（静默截断是本仓点名的「显示不完整却不提示」）。
- `maskEcho` 改成按真实长度给点号 → 「掩码长度不泄密」那组红。
- `append` 的 id 从 0 起 → 「丢了历史之后最早那条的 id 不会撞上 0」那组红（`dropped()` 的 `0` 哨兵
  于是与「丢掉过」同形，而界面据此写滚动提示行）。
- `trim` 就地改（返回同一份数组）→ 「trim 返回新数组」那组红（React 的 `setState` 看不到变化）。
- ⚠️ **`flatten()` 跨宽度缓存** → 「宽 4 是 5 行」与「宽 2 是 5 行」两组同时红，而症状是滚动错位。
- ⚠️ **`decodeTurns` 的类别判据用 `in` 而不是 `Object.hasOwn`** → 「`Object.prototype` 撞不出类别」那组红
  （`{"kind":"constructor"}` 会被当成一个真类别而**不抛**）。
- ⚠️ **`decodeTurns` 对不认识的 `kind` 降级成 `note`** → 「未知类别即抛」那组红，症状是**一句本包自己说的话**。
- ⚠️ **编解码给选填键补上 `undefined`** → 「选填键不在字节里就不许有那个键」那组红（`toEqual` 绿，
  而下一次写出的字节与上一次不同）。
- ⚠️ **往返只比「解出来看着一样」而不比字节** → 键序一改就红，那组断言正是为此逐字节写的。
- ⚠️ **`rowsOfTurn` 的 `case "user"` 交回 `{kind:"echo"}`**（两档里**六条**同时转红：`user` 独占那一档 /
  它与命令回显色档不同 / 逐段都带 `user`）—— 实测 **6 failed | 64 passed**。
  ⚠️ 症状与本包今天那个 bug 逐字同形：气泡那个出口的判据恒假，屏上一个气泡都不画。
- ⚠️ **折行时只有第一段带那一档 `kind`** → `rows` 那一档里**两条**转红（逐段 `kind` 与含 `\n` 那一组）——
  实测 **2 failed | 68 passed**；症状是气泡左边参差不齐（第二段起那几行退化成普通行）。

## 编译期锁（⚠️ 与运行期判据是**两件事**）

`@/lib/log/turn.js:rowsOfTurn` 的 `switch` 穷举六个变体，`default` 那一支形参是 `never` ⇒
**多一个变体时 `tsc` 就红**，不是运行期静默少一行。牙齿：`turn.test.ts` 的「摊平的层**不认** `Turn`」
—— ⚠️ 而它锚的是**今天活着的形状**（`rowsOfTurn` 对六档都给出结果），不是点名某个内部函数：
后者在函数改名后会**恒绿**。

⚠️ **变体数是六这个事实本身**要由 `satisfies readonly Turn[]` 那条钉住（编译器逐字核那六个字面量），
运行期只补「六档都摊出一行」。⚠️ **两张清单不是同一个数**：`Turn` 六档、摊平之后的 `LogRow` **七档**
（`user` 是新加的那一档），而 `codec` 那一档的组合数是 **6 × 7 = 42** —— 说「七档」时先问是哪一张表。

## 五档共用的量具与判据纪律

- **`_shared.ts` 只造数据**（`toolTurn` / `entry` / `textsOf`），**零 IO、零 `describe`、零 hook** ——
  import 它不会注册任何东西。⚠️ 摊平那批用例之所以把行装进 `tool-result` 那一档，是因为
  **结果区那一格装的是 `Turn` 而不是 `LogRow`**，而折行/截断的判据对象是 `LogRow`。⚠️ `rows` 那一档
  **反而要自己造 `user` 那一档的 `Turn`**（它量的就是那一档怎么折）。⚠️ `codec` 那一档
  **不引 `_shared.ts`**：它要的是**每一档一个变体**（共 42 个组合），而 `entry()` 那三个工厂造的是
  「一格 `tool-result`」—— 用它就等于只测到 7 行里的 1 个载体。
- ⚠️ **`clipped` 断言必须逐行分开**：写 `every(clipped)` 会因为**表头没截断**而红，而那不是缺陷
  （表头只有一列、装得下）。这一条纪律写在 `layout.test.ts` 的用例注释里。
- ⚠️ **宽度为 0 那一条**：行数由条目结构决定，与宽度无关，故摊出的是 2 行空串而**不是 0 行**。

## 本目录测不到的一半

⚠️ 这里量的是「**行被算成什么样**」，测不到「**屏幕上有没有真的这么画**」—— 后者是
`tests/layout/` / `tests/render/` 的假 TTY 真渲染那两档的活，而它们读的是 `flatten` 摊出来的同一批行。
两者分开的理由：呈现层一改（换 `Text`、换 padding）不该让纯函数那一档红，而纯函数一改必须让呈现层红。
⚠️ **`tests/render/user-bubble.test.ts` 量的是「给定一段已折好的文字」**，而「一段折行 = 若干行、
每行一段文字、每行都带 `user` 那一档」归本目录的 `rows` 那一档 ⇒ 两边合起来才是「用户消息那一块」那一条。
