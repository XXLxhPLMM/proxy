# tests/theme/ — `@/theme`（语义 → 颜色 / 字形）的纯函数断言

本目录回答「一个语义落成哪一档颜色、哪一个字形」。**零 IO、零 React、零 Ink、零 `process.*`**
（组合根采一次往下传），故这里能**逐字**断言色档与字形，而不必起一个 Ink 去截图。

⚠️ **本目录已有两档**，故主题级不变量归这份 `AGENTS.md`；⚠️ **单个档的文件头只留「这一档管哪一段 +
指向本文件」**，不许把同一段不变量抄成两份 —— 抄的那份没人更新，而**腐烂的那份永远没人读**。

被测模块的不变量归 `src/theme/AGENTS.md`；这里只记「本目录这一组断言共同成立的那些前提」。

## 档位地图

| 档 | 答什么 |
| --- | --- |
| `theme.test.ts` | `themeOf` 取出来的那份主题：**遮罩态**的底色链（遮罩最深、卡片次之）、前景压暗幅度，以及**加的那两档**（用户消息的底色 / 推理强度）与输入区选区那一对反色 |
| `marks.test.ts` | 记号那一族：`runMarkOf` 的三档真值表（字形 + 色档）+ **「跑完了但你没看」那第四档**（字形与色档都与其余三维不同），以及它与 `connectionMark` / `toastMark` 的字形共用 |

## 四条跨档共用的主题级不变量

1. ⚠️ **输出必须逐字唯一**：两个不同的事实**不许**渲染成同一个东西 —— 一个「连接失败」与一个
   「从来没试过」长得一样，操作者就分不出「卡住了」与「还没开始」。这是**色档**那一族与**字形**那一族
   **各自**要守的，而它们的形状不同：色档那条靠「每档一个值 + 取值两两不同」，字形那条靠「每档一个字形
   + 字形两两不同」—— ⚠️ **三档里 `idle` 的字形是一个空格**，所以「三个字形互不相同」也正是
   「那一格恒存在、两帧的列位一样」的那一半。
2. ⚠️ **字形是状态的第二通道**（色盲用户与 `NO_COLOR` 环境下两者都靠形状读）：三张记号表
   （`connectionMark` / `toastMark` / `runMarkOf`）**刻意共用字形** —— 同一个字形在不同语境里必须指
   同一件事。⚠️ 而三张表的**色档不许撞车**：撞车的话「无色终端」那一层就没有别的通道了。
3. ⚠️ **不上色时每一档都是 `undefined`**（而不是换一套灰阶）：灰阶仍会被读成「这里有分级」。⚠️ 故
   「`ok` 真的偏绿」那一条只在 `color: true` 的那一份主题上有意义 —— 无色档上它是 `undefined`，
   判据写成「绿通道最高」而不是「等于某个 hex」正是为了让它对**改配色**免疫（改了配色忘了改表那种事故）。
4. ⚠️ **「两两不同」按「刻意同值的那一族先划出来」量**：`reasoning` 与 `warn` 渲染成同一个颜色是
   **结论**（两处语境、屏上从不相邻），把它们算成撞车的话那条判据就再也不会红 —— 而一个再也不红的
   判据比没有判据更坏（它假装在生效）。

## 判据为什么这么写（四条，各自有牙齿）

- ⚠️ **判据是**深浅（三通道之和）**而不是「两个 hex 不相等」**：后者对「遮罩比卡片还深」那种**方向
  反了**的实现**恒绿**，而那正是不变量 1 要挡的东西。
- ⚠️ **「真的偏绿」判的是「绿通道最高」**而不是那个 hex 字面量：抄字面量等于把配色档的值复制一份到
  测试里，于是「改了配色忘了改这张期望」会绿。
- ⚠️ **压暗幅度判的是「与遮罩的差距」而不是「压的系数」**：系数是实现，差距是不变量。
  ⚠️ 三通道**各自**四舍五入，故深度和的误差至多 1.5 —— 那 2 是取整的余量，不是放水。
- ⚠️ **键集与值是两条判据，不是一条**：不变量 3 那句「每档都是 `undefined`」**挡不住漏写一档** ——
  漏写时 `theme[tone]` 同样是 `undefined`，而「值是 `undefined`」与「键根本不存在」在屏上一致、
  在**类型上却不一样**（后者是漏掉了一档的承诺）。故另有三条量**键集**的判据（三份表的键集都等于全部档位）。
  ⚠️ 同一条纪律的别名：「判据必须落在『键在不在』上而不是『值是不是 undefined』」。

## 各条负载在哪

| 变异 | 转红的判据 |
| --- | --- |
| `scrim` 调成比 `panel` **浅**（亮遮罩） | 「遮罩是那一层里**最深**的一档」 |
| `panel` 调成比 `scrim` **深**（卡片沉进遮罩） | 「卡片比遮罩**亮**」+「四档底色排成**一条链**」 |
| `veiled()` 少盖一档（`muted` / `bubble` / `reasoning` 任一漏掉） | 「**每一档前景都被压过**」+「`bubble` 的底色压到读不出来」+「`reasoning` 那一档是**前景**」 |
| `VEIL_TEXT` 改成 1（= 不压） | 「与遮罩**只差至多一成**」 |
| `veiled()` 全部前景给同一个值 | 「遮罩态的前景**七档两两不同**」 |
| 遮罩态的 `hover` 与 `surface` 取成同一个值 | 「遮罩态的**背景两档仍彼此可分**」 |
| `PLAIN` 里漏掉一档 | 「**三份表的键集都等于全部档位**」（而「每档都是 undefined」那条**不红**） |
| `SELECTION_INK` 的字色换成 `selected`（同色） | 「选区是**真反色**」 |
| `RUN_MARKS.done` 的色档从 `ok` 换成 `accent` | 本档 `marks` **三条** + `tests/layout/` 盯着屏面记号颜色那一档（**跨档**） |
| `runMarkOf` 的 `&& !seen` 去掉（「看没看」**根本不被读**） | 本目录**五条** + `tests/layout/sidebar` 那四条（实测九条同时转红） |

⚠️ 最后那一条暴露了那一族判据的**形状要求**：「读没读 `seen`」这种「一个布尔参与判据」的变异，
只有在**同一帧里同时喂两种值**（看了 / 没看）时才有鉴别力 —— 一个「压根不读那个布尔」的实现，
在「两种值喂的是同一个」那一族判据上恒绿。
