# tests/decode/ — `@/lib/decode` 声明式收窄组合子的真值表

本目录只答一件事：`unknown` → 声明形状之间那次**显式收窄**在哪些输入上抛、抛的那句话长什么样。
机制与层不变量归 `packages/tui/src/lib/AGENTS.md`。

收窄组合子的运行期调用点**只有** `@/api/wire.js`，而服务端是**另一个进程**（甚至另一台机器），它的响应
不经过本包任何一行类型检查 —— 故这一档存在的理由与 `tests/wire/` 是同一条：**「对面变了」怎么变成一句
看得见的话，而不是一片空白。**

## 文件

- `scalars.test.ts` — **叶子那一族**：一个值进、一个值出且不递归 —— `str` / `num` / `bool` / `oneOf` /
  `opaque`，以及只改 `null`、`undefined` 处理的那两个包装 `nullable` / `optional`。
- `structure.test.ts` — **容器那一族**：`arr` 与 `obj`。全模块只有这两个**递归**，故「操作者靠
  `body.keys[1].id` 定位到具体那一格」这条不变量只有它们担得起。
- `error-messages.test.ts` — **跨族**的错误文案纪律：逐族各来一份样本（`num` 叶子、`arr(obj(...))`
  容器、`str` 叶子），因为它约束的是**所有**族共用的那条出口。
- `_shared.ts` — 三档共用的 `REQ` / `expectShape` / `SECRET`。⚠️ **不是** `*.test.ts`，故 vitest 不收它
  （`include` 只收 `tests/**/*.test.ts`），不会变成空的幽灵档。
- `AGENTS.md` — 本文件。

## 为什么分三档：分界是**递归与出口**，不是组合子的个数

叶子与容器的判据形态根本不同 —— 容器要断言**路径被逐层拼出来**、要验**下标**，叶子两者都不适用；
而错误文案那一族同时引用两边的组合子，塞进任何一边都是任选。分界因此落在「递归」与「共用出口」上，
不是落在「有几位组合子」上。

⚠️ `expectShape` / `caught` / `REQ` / `SECRET` **必须**是同一份：抄成三份的话，改一处漏掉另两处，而
症状是「某一档的红由另一档的改动造成」—— 最难查的那一种。

## 导入纪律

⚠️ 收窄组合子**不从 barrel 取**：`src/lib/index.ts` 那条转发是后来加的，而全包唯一的调用点是
`@/api/wire.js`（走深层路径，否则 `api/index → api/wire → lib/index → … → services → api/index`
是一条运行期环）。故本目录同样经深层路径取 —— 与根仓
`tests/unit/manager-http.test.ts` 直接 import `@/manager/routes/patch.js` 同一口径。

## 本目录盯的事故

1. **类型不符一律抛 `shape`**（不是放过、不是 `undefined` 顶替）。`kind` 必须落在
   `shape` 那一档：把「对面版本对不上」显示成「内部错误」会让人去翻服务端日志里一行根本
   不存在的东西。
2. **`nullable` 与 `optional` 严格分工**。`JSON.stringify({a: undefined})` 产出 `{}`，故
   服务端「没这个字段」在线上是**键不存在**而不是 `null`；用 `nullable` 去收会让「服务端没配
   配额」被判成「配了个坏配额」。而 `undefined` **必须**在 `optional` 才合法 —— 把两者写成
   都接受，「服务端没给这个字段」就会被当成「服务端给了 null」。
3. **错误文案里一个字节的值都不许带**。形状不对的那串字节来自一个本包不认识版本的进程，
   它既可能是凭据也可能是名单；把它打印到终端等于把对面的数据抄进本机的滚动缓冲。

## 判据为什么这么定

- 判「抛不抛」与「抛的是什么」分开断言：判 `kind` / `code` 是契约（界面据此分档），
  判文案里的路径与期望类型是**可用性**判据（操作者要靠它知道该去看哪个字段）。
- 「文案不含原值」这条**必须**与「文案确实说了点别的」成对断言：单独一条 `not.toContain`
  在文案为空串时也会绿，而空文案正是这条纪律失效后的样子。

## 防假绿的位置

- `caught()` 在「没抛」时显式抛错并说明该抛什么 —— 用 `expect(fn).toThrow()` 之外的手段取到
  错误对象，避免「断言的是包装后的 message 而真值恰好不含那句 secret」这种错位。
- `arr` 的元素收窄那条断言错误路径里带**下标**：只断言「抛了」的话，`arr` 退化成
  `Array.isArray(v) ? v : bad(...)` 也照样绿，而那正是「收窄了容器、忘了元素」那条事故。
- `strArr` 与 `arr(str)` **逐字等价**是本模块的组合子恒等式，故那一条用两个入口各收一次空数组与
  非数组：只钉住一个入口时，另一个入口整体退化成透传也照样绿。
- 「文案不含原值」的样本必须真的**触发**失败才有意义 —— 一个「类型就对」的输入压根不产生文案，
  那时 `not.toContain` 是对着空气判绿。

## 相关路径

- `packages/tui/src/lib/decode.ts` — 被测模块；`packages/tui/src/lib/errors.ts` — `shape` 档与 `TuiError`。
- `packages/tui/src/api/wire.ts` — 全模块**唯一**的运行期调用点（`tests/wire/` 是它的判据面）。
- 根仓 `src/manager/routes/*.ts` — 被收窄的那些形状的出处。
