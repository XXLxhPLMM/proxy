# tests/providers/ — provider 清单 + 模型清单 + 会话的模型选择

被测模块是 `@/services/config` 的 `provider.ts` / `store.ts` 那一面与 `types.ts` / `validate.ts` 的两个纯函数。
真库 + 真临时目录、零网络。

## 锁住的是「哪一条路错了」，不是「函数存在」

- **存储键那一族**锁的是**按第一个 `/` 切**：按全部切分的实现会让 `openrouter/anthropic/claude-x`
  的 providerId 变成 `openrouter/anthropic`，而屏上两个 provider 长得一模一样 ⇒ 用户选了另一个模型。
  ⚠️ 故判据用**三段键**，并配一条「拆拼互逆」的往返。
- **往返与顺序那族**量的是**从外面倒出来的落盘字节**（`_shared.ts:withRaw` 的原始句柄），不是读面返回了什么 ——
  用本包自己的接口去量就是自证。⚠️ 顺序那条钉的是 `rowid`：**整份换掉之后 `rowid` 必须跟着数组序重排**。
- **级联删那族**量的是「两张表上都没有孤儿行」：一个只删 `providers` 那一行的实现，
  库里会攒出一批指向已删提供商的模型，而 `readProviderModels` 读它们时那个 provider 早就不在了。
- **打码那族**与 `tests/ledger/` 那一条同规格：**绝不返回半截明文**、**空串保持空串**，
  并与 `REDACTED_TOKEN` 反向对照（两个不同的真凭据不许看起来一样长）。

## 三条档内纪律

- ⚠️ **坏内容即拒的那些档必须钉「盘上那一份逐字未变」**：只断言「抛了」的判据，在一个「抛之前先整表清空」
  的实现上照样绿 —— 而那正是我们要防的事故（清空之后下一次写就把存着凭据的那份覆盖掉了）。
  ⚠️ 造坏形状一律用 `withRaw`（**先 `closeLedgerDb()`**：句柄开着时改的不是包自己下一次会读的那一份）。
- ⚠️ **拒写必须钉「真的一格都没写」**：写面先校验再开事务，而判据是读回来仍是缺省那一档。
- ⚠️ **每一条「不许含某样东西」都配一条反向自检**（判据真的判中过 / 盘上真的多了一行）：
  负向断言天生怕空——探测器什么都没产出时它恒绿。

## 单例的开关顺序

`providers.ts` / `store.ts` 的每一次读写都走 `db.ts` 里**同一个**模块级句柄。故**每一档都自带同一个
`afterEach`**（`closeLedgerDb()` → `removeCreated()`），两步顺序照抄：先收句柄（句柄开着时 Windows 上那个目录删不掉），
再删临时目录。⚠️ `_shared.ts` 注册不了 hook（模块没法把 `afterEach` 塞进引用它的档），故**动作**住在共享模块而
**注册**留在各档。

## 档位地图

一个子主题一份档；档名取自那一组 `describe` 断言的东西。

## 与别的目录分工

`tests/ledger/` 锁**台账（targets）那份数据**的成败语义，`tests/sqlite/` 锁**那个库本身**与另外几张表的落盘，
本目录只锁 provider 那两张表与 `sessions` 里那两列。⚠️ 故「库不存在 ⇒ 空清单且**不**建库」「坏内容即拒」
这两条**同族**的判据在本目录出现而答案一致 —— 它们验的不是同一件事。
