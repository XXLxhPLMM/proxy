# tests/complete/ — `@/commands/complete` 的行为面：当前这一行 + 光标位置 → 建议

本目录只答一件事：**这一行加上光标位置，该给出哪些候选、以及补完之后那一行变成什么样**。
解析那一侧的判据在 `packages/tui/tests/parse/`，命令面板那一侧在
`packages/tui/tests/palette/`。

## 档位地图

一个子主题一份档；档名取自那一组 `describe` 断言的东西。

| 档 | 答什么 |
| --- | --- |
| `candidates.test.ts` | **候选表**：每个形参位置该出什么，以及排序与去重 |
| `boundaries.test.ts` | **退化输入**：位置不在闭合集里 ⇒ 零候选；光标坐标畸形 ⇒ 夹住而不抛 |
| `line-output.test.ts` | **补完之后那一行**：只重写光标所在那个词；带空白的候选插入时必须加引号 |
| `_shared.ts` | 三档共用的 `NAMES` / `at()` / `cands()`。⚠️ **不带 `.test.ts` 后缀的不会被 vitest 收集** |

## 本目录盯的事故

1. ⚠️ **补全吃掉用户已经敲好的东西**。补全在句子中间被按（Tab）时，界面上看不出差别，而用户敲好的
   后半行 —— 一个流量上限、一条 token —— 会消失。那是本工具能造成的一类最贵的数据丢失（凭据要重敲、
   地址要重新找），而 `pnpm typecheck` 与 `pnpm lint` 看不见它。故 `line-output.test.ts` 的核心断言是
   「光标之后的每一个字节逐字不变」，并且**做过变异**：把补全改成按整行重建，断言必须转红。
2. ⚠️ **命令名归命令面板，不归补全**。命令名是一个 19 行、带说明、能上下走的面板，与「这一个词后面
   能接什么」不是同一个问题；两层都答「命令名的第一个候选」的话，`/c` 会得到两个不同的命令
   （这里按字典序、那里按表的顺序）。「命令名」**曾经**也是候选之一。
3. ⚠️ **一行已经错了就不提候选**。位置不在闭合集里时提候选，等于让人在一行错话上继续敲；而这一条与
   「命令名归面板」是**两件不同的事** —— 合成一条断言的话，「因为判据太宽而给了候选」与「因为该给
   而没给」会互相掩盖。
4. ⚠️ **值格与凭据格永不给候选**。token 与新密码不是能补出来的东西；一个空列表在界面上看不出是
   「没有」还是「有但没匹配」，所以这两格必须逐个钉住恒空。

## 候选只许来自两个数据源

某个形参位置上的 `choices`（组名 `target` 的下一段、`user set` 的字段名、`help` 的主题）与调用方
喂进来的台账名字。任何「哪个更常用」式的排序都会让列表随实现细节漂移，故排序判据只有三个，全部是
「两个字符串」的纯函数（字典序 + 前缀收窄 + 去重）。

⚠️ **不许自己去读台账**：台账名字只从 `targetNames` 进来。喂进来的清单是空的 = 没有名字可补。

## 负向断言的锚点

全部是**输入**（`/user pass bob ` / `/target add n url ` / `/user set bob quotaWindow `），不是符号名 ——
点名一个不存在的符号，断言会恒真而不是失败（根 `AGENTS.md`「写护栏时」）。

## ⚠️ `at()` / `cands()` 那个 `|` 约定

用例把光标写成一行里的一个 `|`（如 `target switch pr|od extra keep`），`at()` 取它当落点、去掉它、
再**补上 `COMMAND_PREFIX`**。⚠️ 它只做这三件事：不替用例推断别的任何东西 —— 一旦它开始猜，
「行首那个 `/` 还在不在」那道闸就会从用例里消失，而那道闸正是 `boundaries.test.ts` 钉住的东西。

⚠️ `NAMES` **乱序**给出：它同时是「排序不许依赖喂进来的顺序」那条判据的输入，而一个已经排好序的
样本会让那条判据恒绿。

## 防假绿的位置

- ⚠️ **前缀那道闸钉在「光标在行尾」的那一行上**（`user set bob ` / `target switch `）。空输入行上取消
  那道闸**仍然**给零候选（命令名不归补全层，而空行光标就在 0 处），于是一个「前缀闸可以删」的结论
  会从那些用例上溜过去。
- ⚠️ 夹到行首之前时那一格**连命令名都还没开始敲**，给候选就是在诱导：夹的职责是「不抛」，不是
  「凑一个答案」。
- ⚠️ 光标压在**空白**上时那个空格**就是**光标词（与 shell 的 complete-word 一致），而光标在某个词的
  第一个字符上时替换的也是那个词 —— 这两条**故意相反**，少写清一条就会把形参次序记反。
- ⚠️ 「本层只承诺不吞字，接不接受多出来的词由界面层决定」：光标落在空白上时结果是四个词，**那不是**
  本层要管的事。把这条断言挪进本目录就会得到一个恒红的用例。
