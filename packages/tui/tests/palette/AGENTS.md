# tests/palette/ — `@/commands/palette`（命令面板）的纯函数断言

被测模块在 `@/commands/palette.js`，零 IO、零渲染；面板的**几何**（占哪几行）在
`@/lib/geometry.ts`，**呈现**在 `@/app.tsx`，两者都不在这里。六条不变量分三档：
`rows.test.ts`（①开 / ②列全表 / ③高亮是纯函数）、`navigate.test.ts`（④补完 / ⑤移动与滚窗）
与 `enter.test.ts`（⑥`Enter` 也接受高亮）。

**锁什么**：六条不变量 —— ①面板的**开**只有一条判据（整行以 `/` 开头）；②列的是**全表**
而敲出来的东西只定高亮（否则 `↑`/`↓` 走一步就无路可走）；③高亮是**输入行的纯函数**
（界面上没有「高亮在第几行」这个状态，故不存在「输入行 A、高亮 B」那一帧）；④`↑`/`↓`/`Tab`/
鼠标点/`Enter`**共用同一个补全实现**，而它只换**命令名那一段**、形参原样留着；⑤`↑`/`↓`**到头停住**
而不循环，滚窗负责让高亮**始终可见**（循环会让「到头了」这件事永远按不出来）；⑥**`Enter` 的结论只
落在「接受高亮之后**命令名**变没变」**，改不了就提交 —— **不是**「命令名敲全了没」（`/help` 敲全了高亮
就是它自己，按后一条判的话这条命令按多少次回车都跑不了），也**不是**「光标动没动」（挪一下插入符
不是一次补全），更**不是**「形参的值补没补」（那是 `Tab` 的活，`complete()` 是它的另一个出口）。

⚠️ **命令名恒是一个词**（命令表里没有组，故命令名不再跨空白）：于是「两段命令名的尾随空格」那一族
问题在命令表变了之后**不存在**，而 `PaletteRow` 上那个「补不补空格」的字段也跟着删了 ——
留着它就是一个恒假的字段（而恒假的字段比没有更坏：它看起来像一道还在生效的闸）。

## 为什么拆掉哪一处会红

- 「开」的前缀那道闸去掉 → 「不带前缀的行不开面板」那组红（且**没有**别处会红）。
- 列表改成「按敲的东西过滤」→ 「`↓` 能一路走到底」那组红：填完 `/clear` 之后列表塌成一行。
- 高亮改成 `at` 自己累加（不再是纯函数）→ 「高亮跟着输入行走」那组红。
- `paletteFill` 改成替换**整行** → 「形参原样留着」那组红（`/usag| alice` 丢掉形参）。
- ⚠️ **完全相同的那一条不优先** → 「`/r` 高亮到 `/r` 本身」红：表里 `rename` 排在 `r` 前面，
  只按「以它开头」挑的话 `/r` 会高亮到 `/rename`，于是 `Tab` 补出一条他没敲的命令。
- **命令名那一段取整行**（而不是第一个词）→ 同上那组红：`/usage alice` 的命令名会变成
  `usage alice`，而 `paletteFill` 换掉整行 ⇒ 操作者敲好的形参消失。
- `paletteFill` 的光标落在**行尾** → 「`fill` 之后插入符落在刚写进去那一段的末尾」红。
- `paletteFill` 直接拼 `row.path` → 「不许把前缀写两遍」红（`//status`）。
- `paletteWindow` 换成 `clamp` → 「高亮被顶到视口最后一行时才滚」那组红。
- `paletteStep` 改成循环 → 「到头停住」那组红。

## ⑥ `Enter` 那一档：判据是「这一行变没变」

- **按「命令名敲全了没」判** → `enter.test.ts`「`/help` 敲全了按 Enter 就提交」红（而症状是屏上**完全
  没有反应**的那一种：`/help` / `/status` / `/acl` 全部跑不了）。
- **一律 `fill`** → 「三档 `submit` 逐档」与「每一条命令名敲全了都是 `submit`」红。
- **一律 `submit`** → 真值表里三行 `fill` 红。
- ⚠️ **判据里带上光标**（`filled.line === line && filled.cursor === cursor`）→ 「**同一个行、两个光标、
  同一个结论**」红（`/usage ` @7 与 @6 必须是同一个 `submit`）+「两下之内到 `submit`」红。
  ⚠️ **这一条不能写成负向源码断言** —— 「比对里不含光标」那种文本判据对着一个已不存在的写法恒真，
  故判据是「同一行 + 两个光标 + 一个结论」。
- **`Enter` 顺手调 `complete`** → 「不做形参的值补全」红（它带着一条正向对照：同一行 `Tab` **确实**
  补成另一行 `/help status`，而 `Enter` 一行都不改）。
- **另抄一份接受逻辑**（不调 `paletteFill`）→ 「共用 `paletteFill`」红（`Tab` 与 `Enter` 的补全各不相同）。
- **填出来的光标不自洽** → 「`fill` 之后插入符落在刚写进去那一段的末尾」红。

⚠️ **代价是数出来的，不是估出来的**（`enter.test.ts`「从敲第一个字到跑掉要按几下」那一档）：
单段零形参 **1** 下、单段带形参 **1** 下 —— ⚠️ **只有两档了**（命令名恒是一个词 ⇒ 没有「两段」那一族），
而那一档**逐条重算全表**（18 条命令）并**按命令表那份形参表分档**，⚠️ 且**顺带把「全表只有那两档」这件事
本身钉住**（否则那张表钉的是同一档多遍）。
⚠️ **半截名字仍是两下**（补一次 + 提交一次）：补全那条路是「名字没敲全」，而跑掉的是补全出来的那一条，
不是他没敲完的那一条（否则「按一下就跑一条别的命令」）。

⚠️ **两条「不是变异的变异」**（实测是绿的，故它们**不是**这条护栏在生效的证据）：
- 把 `complete` 的 `cursor < lead` 判据删掉 —— 那一半被「`startsWith`」**同时**挡着，
  单独删它没有可观测后果（真正的牙齿是 N2 与 N3 的组合）。
- **M17 是可证明的等价变异**：`outputRows = max(0, outputBlockRows - 1)`，故 `outputBlockRows ≥ 1`
  时 `outputRows + 1 === outputBlockRows` 逐字相等；而 `outputBlockRows === 0` 时那个恒等式
  让「多画的一行滚动提示」正好落在结果区**本来就有的**那一行空位里（结果是**不溢出**）。
  它真正被挡住的地方是 ⑥ 的恒等式「`outputBlockRows + 面板 === 内容行数`」—— 那条一旦破，
  这一行就无处安放。

⚠️ **M21 与 M22 是命令表变短之后重写的两条**（原来那两条讲的是「两段命令名」）：今天判据落在
「命令名恒是一个词」与「光标落在刚写进去那一段之后」上，而 M21 那个变异（取整行）在新表上照样转红。

⚠️ 早先那条「面板画在结果区前面 → 真渲染看不见」也已作废：面板现在**自己占行**，两者
画在同一列里依次排下去，`flexDirection` 的先后**看得见**（N16 就是靠它转红的）。
