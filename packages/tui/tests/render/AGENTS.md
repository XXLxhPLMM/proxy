# tests/render/ — 输入行、模型状态行与**用户消息那一块**的**真渲染**断言

本目录回答「这几块**新形状**画出来的那一帧，逐格对不对」：**箭头槽**与**选区反色**、
**「提供商 · 推理强度」那一行**、**用户消息气泡**。判据全部跑在真的排版结果上（假 TTY 喂进真 `Ink`），
与 `tests/layout/` 同一形状。

## 为什么要单独一个文件夹

`tests/layout/` 量的是**整屏那一大片**（侧边栏那一列、模态卡片、遮罩那一层）。而这三块有两个特点
使它们量不进那一档：

- ⚠️ **它们是整屏里的小块**，判据要的是「那一格是什么色 / 那一列是什么字」而不是「整帧里有没有这一句」
  ⇒ 走 `_probe.ts` 那一族（`bgAtColumn` / `rawIndexOfColumn` / `columnOfIndex` / `sgrColorAt`）。
- ⚠️ **用户消息那一块不是 `RegionProps` 的形状**（它拿 `text` + `width` + `theme`），而**行模型今天还没有
  「用户消息」那一档**（`@/lib/log` 那一侧要把它从 `echo` 里分出来）⇒ 走 `@/app.js` 的整屏渲染量不到它。
  故这一块用 `renderElement`（`_harness.ts` 那个**唯一**不在转发清单里的东西）单独渲染。

## 共用的那半边

- ⚠️ **`_harness.ts` 从 `../layout/_harness.js` 与 `../layout/_probe.js` 转发**，不复制也不搬 ——
  复制一份就是两套探测器（而探测器一旦认错了东西，症状与「实现坏了」在屏上完全一样）。
  ⚠️ 而**正解是把那两个模块提到 `tests/` 根**：它们今天的收件门槛是九个档（见 `tests/layout/AGENTS.md`
  「共用的那半边」那一条），即**本来就住在错的地方**；搬动要一次改九个档的 import，留给集成那一轮。
- ⚠️ **每一档自带 `vi.hoisted` 那一句**（`FORCE_COLOR` 必须在 ink / chalk 被 import 之前设好）——
  `vi.hoisted` 只在**入口模块**里被提升到 import 之前，放进 `_harness.ts` 就是一句普通调用，
  跑在 ink 之后 ⇒ 那一档的着色判据**整档恒真**。

## 档位地图

⚠️ 四档共用三件**只有真渲染才看得见**的事：① **Ink 对过宽的 `<Text>` 是静默软换行**（一换行后面所有行
都往下移）；② **带底色的 `<Box>` 整块被写成带底色的空格**（而 `<Text>` 从最近的带底色的祖先继承 ——
所以「气泡右边缺一块」与「在那一格戳了个洞」是两种不同的实现错误）；③ **反底色那一格与「真反色」那一段
是两件事**（前者的底与字同档，后者必须两档相反）。

| 档 | 答什么 |
| --- | --- |
| `composer-gutter.test.ts` | 箭头槽**贯穿整个输入内容高度**、字形恒在最上面那一格、下面每一格一竖线；硬换行与软折**都**竖直对齐；那一列**只覆盖文本行**（框内那行瞬时消息头上没有竖线） |
| `composer-selection.test.ts` | 选区是**真反色**（两档不同，逐格量）；选区**外面**不带那一层底色；选区与插入符是**两个通道**（恒不同时出现）；**跨行**选区在每一行都被夹住 |
| `model-status.test.ts` | 三段**各有各的色档**；「未选择」是中性档；画在**几何给的那一行**且与输入框里的字**竖直对齐**（缩进恒多出左边框那一列）；框外、状态行之上；几何给 `null` ⇒ **整行不画** |
| `user-bubble.test.ts` | 左边距一列 + **恰好一枚**箭头（与输入框同一列宽）；那一行**每一格**都是 `bubble` 底色；**命令回显那一行没有底色**；超长的一段被裁而那一行仍恰好那一宽；**接线**那一半（整屏那一帧里 `user` 那一行真的派给了气泡那一支，而命令回显两者都没有） |

## 判据为什么这么写（四条，各自有牙齿）

⚠️ **同色的两个通道看不见**——这一族最贵的坑，且它有两处独立的形状：

- **选区那一段**：只判「那一段带 `selected` 底色」的版本**照样绿** —— 而屏上那一段一个字都读不出来。
  故判据必须**前景与背景两个都问**，且要配「有选区时屏上没有一个格子是同色反底色块」那一条。
- **推理强度那一档**：`reasoning` 与 `warn` **逐字同值**，所以颜色判据**恒绿**，那一档只能**从源码现取**
  那一档名 —— 而「从源码取」必须配「正向对照」（探测器今天取得到那一行）与「注释不算数」（`codeOnly`）。
- **文字色那一档**：同色的话屏上「我说的话」与「刚执行的命令」靠**底色**那一个通道分，而无色终端里压根
  没有底色 ⇒ `USER_TEXT_TONE` 必须有独立的判据。

⚠️ **接线那一半的判据必须落在屏上那两个通道**（`bubble` 底色 + `muted` 字色）而**不是**「分派用的那个
集合里有 `user`」—— 后者是内部结构，一个恒真的内部断言与「屏上根本没有气泡」症状完全一样。
⚠️ 而那两条断言**必须同属一个 `it`**：只有「`user` 有底色」的话，一个把**所有**行都画成气泡的实现照样绿。

⚠️ 一条被实测否掉的假设：「气泡要自己补齐到整行」—— **是错的**：Ink 把带底色的 `<Box>` 整块写成带底色
的空格，于是删掉那段补白**渲染结果逐字相同**（实测绿过一次）。真正 load-bearing 的是**外层那个
`<Box backgroundColor>`**（删掉它那一行就没有底色了）。
