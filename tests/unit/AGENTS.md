# tests/unit — 纯逻辑与源码级断言（52 个文件）

## 路径说明

不起监听端口、不拨号，构造对象直接调。三类内容：

| 类别 | 判据 | 例 |
|---|---|---|
| **纯逻辑单测** | 构造对象 / 纯函数直接调，无网络 | `acl.test.ts`、`auth-users.test.ts`、`json-file.test.ts` |
| **端口契约测试** | 断言 `ProxyOptions` 上三个可插值端口的形状与缺席语义 | `access-control-port.test.ts`、`core-context.test.ts` |
| **源码级护栏** | 读源码文本断言「某件事没发生」。扫描实现全在 `../helpers/source-scan.ts` | `no-external-network.test.ts`、`pack-contents.test.ts`、`dead-optionality-cleared.test.ts` |

## 硬约定

- **零外网**、**不落盘**（两条的完整判据见 `tests/AGENTS.md`）。需要断言日志的用例必须注入自己的 `LoggerImpl` 并把 `logFile` 指向临时目录。
- **每条断言的不变量与「为什么」写在这个测试文件自己的头注释里**，任何 `AGENTS.md` 一概不重复。
- **源码级断言必须先 `codeOnly` 去注释**（复用 `../helpers/source-scan.ts` 的同一份实现，字面量与行号口径完全一致）——注释里点名被禁符号是在**描述这条不变量本身**。
- 端口契约测试用**显式 disabled 档**而不是省略端口：另两个端口的缺席读作「关闭一项功能」，而 `access` 的缺席读作**取消防护**（方向相反）。

## 决策清单

1. **负向源码断言不许锚在已删除的符号上** — 那种锚点**恒真**，断言恒绿；它看起来在保护不变量，实际已经不存在它要防的东西。**这是最危险的一类假绿，因为它伪装成「护栏在生效」而不是「护栏不存在」。** 正确做法是把锚换成**被防住的行为在今天仍然存在的形状**（入口调用 / 构造调用 / 值导入 / 出现次数 / 配置读取）。自检清单见根 `AGENTS.md`「写护栏时」。
2. **跨行判据必须整段文本匹配，不能逐行** — 逐行匹配一个天然跨行的判据是同源的另一种假绿形态。
3. **写「幂等」类护栏前先问：第二次调用在实现上凭什么不同？** 答不上来就是恒绿。幂等要由实现里的具体机制提供（例如 `splice(0)` 清空订阅数组），**不许另设一个「已释放」标志来给自己发绿牌**——那个标志测不出来（变异验证：摘掉它行为一字不变），本仓对死可选性零容忍。
4. **零外网护栏必须自己防假绿** — 扫描范围非空且覆盖三个目录、**不含** `helpers/` / `manual/`；拨号位命中数 > 30 且覆盖 ≥3 种建链原语；公网引用 ≥ 50 条。**已用变异测试验证**：往某个 integration 文件塞一处真外网拨号 → 拨号位与普查两面**同时红**。
5. **`pack-contents` 护栏跑真 `npm pack --dry-run --json`** 而不是解析 `package.json` — 因为 npm 的三条事实（`files` 里的路径**无法**被 `.npmignore` 排除；npm **强制包含**任意深度的 README；裸目录名 = 整棵子树）只有真跑一遍才验得到。它同时是**正向断言**（防「白名单收太紧把包收空」）。
