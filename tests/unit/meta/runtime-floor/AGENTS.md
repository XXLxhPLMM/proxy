# tests/unit/meta/runtime-floor/

本目录只答一件事：**Node 运行时地板这个数字不许在全仓任何一处漂**
（唯一真相源 = `package.json` 的 `engines.node`）。
被测对象是**散在十几份文档与源码注释里的地板声明**，不是某一个模块。

## 地板这个数字为什么必须由测试来守

`engines` 在 npm 与 pnpm 上都只是 WARN（退出码 0），`devEngines` 只在 npm 上生效 ——
**没有任何 `package.json` 字段能拦住开发环境**（实测表在根 `AGENTS.md`「开发必须 Node >= 22.13
由谁保证」那一节）。真正强制地板的是 `tests/unit/datasource/quota/sqlite/driver-split.test.ts` 里那条
真跑 `node:sqlite` 的 builtin 档断言，而那份文件里的两个数字（22.5 出生 / 22.13 免 flag）**又被十几处
文档复述**。
数字一多，漂移就是时间问题：地板在文档里被写低，消费者照着装；被写高，开发环境自己起不来，
而**没有任何一处会报错**。本目录就是那道「不会报错」的反面。

## 六档分工（⚠️ 外层 `describe` 在三档里各重开一次，标题不许改）

| 档 | 答什么 |
|---|---|
| `coverage.test.ts` `0 覆盖面` | 扫了多少文件、命中多少处、降级面在哪，以及**每一项排除是不是有东西可排**。**降级面必须看得见** —— 少了这一档，「本目录此刻只覆盖了哪些文本」就只存在于判据作者的脑子里 |
| `truth-source.test.ts` `1 真相源` | `engines.node` 必须是**单一 floor 形态**，且 patch 段恒为 0 |
| `truth-source.test.ts` `判据自检` | 探测器自己有没有写坏 |
| `drift.test.ts` `2 地板声明` | **核心档**：全仓每一处声明地板的形状都必须等于 `engines.node` |
| `drift.test.ts` `3 正向存在性` | `node:sqlite` 的**两个**边界必须在讲分流机制的那几处同时出现（**正向**断言，缺了就红） |
| `drift.test.ts` `4 口径自检` | 跨行形状为零、排除清单没被扩大、未钉的运行时版本提及被普查出来、两份视野构成一个划分 |

⚠️ **判据自检单独成档的理由**：上面每一档都是**负向断言或下限断言**，探测器一旦写坏
（例如比较符的正则少写一个字符），它们会**一起**变成永远通过。

## ⚠️ 自指排除清单：搬一次档就必须改两处

`../../../helpers/runtime-floor-scan.ts` 的 `SCAN_EXCLUDED_SELF_FILES` 排除两份文本 ——
判据自己的素材面（helper 带着合成脏样本）与断言档里**必须逐字写出它要拦下的形状**的那份注释。
判据的形状与判据对自己的描述住在同一份文本里是纯自噬。

⚠️⚠️ **它是一对必须同时改的东西**：那张表 + `coverage.test.ts` 的「自指排除恰好两份」断言
（它**钉的是字面量数组**）。只改一边会得到两种静默失败：

- 表改了、断言没改 → 断言恒绿（它在描述一个旧世界），而「排除真的生效」只剩半截在验；
- 断言没改、表也没改 → 那份注释进扫描面，**今天恰好无害**（命中数恰好都等于地板），
  但下次有人在它注释里写一句「旧版本写成 22.6」那种**故意写错**的声明就会红，
  **而红的原因离真因十万八千里**。

**改完必须做三轮实测**（`pnpm exec vitest run tests/unit/meta/runtime-floor`，别跑全量；
两个方向的颜色是**相反**的，混淆它们就等于把排除清单改反了）：

① **把表里那一条改错一个字 → 必须红。** 不红 = 那条断言恒绿，它在描述一个旧世界。
② 在**被排除的**那份（`truth-source.test.ts`）注释里加一行故意写错的声明 → 必须**绿**。
   它绿**才**证明排除真的生效；它红说明这一份已经不在扫描面里，表没起作用。
③ 在**没被排除的**一份（`drift.test.ts`）里加同一行 → 必须**红**，且失败信息要指出
   `drift.test.ts:<行号>`。这条是新路径**真在扫描面内**的正向存在性：
   若它绿，说明扫描面根本没枚举到 `tests/unit/meta/runtime-floor/` 这一层。

## 「地板」与「边界叙述」是两类东西（这一组最容易做错）

**地板只有一个**：`engines.node` 里那个数。本目录**只**钉它。
22.5（`node:sqlite` 出生）与 22.13（免 flag）是**两个独立事实**，它们在 `src/utils/sqlite/*`、
根 `AGENTS.md`、`Dockerfile` 里的叙述是**合法的机制说明**，不是漂移；判据刻意不碰它们
（理由与判据形状写在 helper 的文件头）。反过来也**不许**把边界叙述漏出视野：
`drift.test.ts` 第 4 组的普查会把每一处在谈运行时、却没被钉住的版本字面量打印出来，
包括上界写法与「数字自己是句子主语」那类判据覆盖不到的形态。

## 三条刻意的口径收窄（写明理由，别当成漏检）

- **大小写敏感的 `Node`**：`node:sqlite` 是**模块名**、`node:22` 是**镜像标签**，都不是运行时地板。
  `Dockerfile` 那句「base image 是 `node:22`（≥22.5，走内置档）」因此合法。
- **桥接窗口里不许有数字**：`Node 16 – 22.12` 这种区间里站着另一个数字，并成一条声明就会
  凭空得到一个地板。窗口上限 48 字符，用来覆盖「运行时名与地板被一截散文隔开」的写法。
- **`lib/` 显式排除**：它是 `build:lib` 的产物、`.gitignore` 已忽略，`.d.ts` / `.js` 里的注释
  是 `tsc` 从 `src/**` 拷过去的，**内容由 `src/` 决定**。扫进去它会红（今天那里面就躺着陈旧
  的 22.5 声明），**红了说明该排除它、不是该改它**。`coverage.test.ts` 单独把它扫一遍来证明
  这个排除确实在干活 —— 否则「排除」就是一句没人验证的空话。

## 防假绿的位置

- **脏样本逐条「会红」**：合成脏文本（`22.6` 顶替地板、`22.5` 被当成免 flag 版本）必须
  **既被识别、又确实不等于今天的 `engines` 地板**。两条合起来才是「它会红」；只写前半条，
  「识别出 22.6 但判定逻辑坏了」照样全绿。
- **合法样本逐条「不红」**：`mustFlag.clean` 是今天真实的写法（相邻 / 隔散文 / 无空格 /
  反引号 / 后缀加号 / 徽章编码），它们必须被识别**且**等于地板。
- **负向样本的锚点逐条是今天活着的行**：`mustNotFlag` / `mustNotPinBoundary` 逐字取自仓内
  真实文本（上界写法、`node:sqlite` 模块名、区间、两个边界的机制叙述、方法学举例）。
  点名一个不存在的形状，负向断言会**恒真**而不是失败。
- **地板扰动自证**：把地板换成一个确定不等于它的值再跑真实扫描，全部命中都必须变成违规。
  判据「会红」这件事因此不依赖任何合成样本，也不依赖今天的命中数。
- **命中数只有下界、没有定数**（`>= 8`）：钉死具体个数会把「加一个文档」变成「改一次测试」的噪音，
  于是人们会去改测试而不是加文档；下界只挡住「探测器整体失灵」。
- **三档必须看到同一份命中集合**：故 `engines` / `scan` / `floor` 住在 `_runtime-floor.ts`
  （进程级单例），而不是各档各扫一遍 —— 否则「覆盖面那档报出的 N」与「漂移那档判的 N」
  可能不一致，而那种不一致看不出是哪一边错了。

## 文件

- `coverage.test.ts` — `0 覆盖面` + `lib/` 排除的牙齿（产物存在时才有，`describe.skipIf`）。
- `truth-source.test.ts` — `1 真相源` + `判据自检`。⚠️ **它是自指排除的那一份**（见上）。
- `drift.test.ts` — `2 地板声明`（核心）/ `3 正向存在性` / `4 口径自检`。
- `_runtime-floor.ts` — 三档共用的 `engines` / `scan` / `floor`（**不带 `.test.ts`**）。
- `AGENTS.md` — 本文件。
