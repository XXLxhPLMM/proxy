    - **写失败用 `vi.mock("node:fs/promises")` 注入**（`probe = vi.hoisted(...)`）。理由是**可移植性**：本仓主战场是 Windows CI，`chmod` 在 Windows 上只切只读属性而句柄已开时写入照旧成功，造不出稳定的真实 `ENOSPC`/`EACCES`。两个坑各踩过一次：① **`open()` 时按当时的开关决定返不返回代理** → 开关晚于 `open()` 时会静默测了个真磁盘（改为**总是**返回代理、`write` 在**调用时**读开关）；② **反射出的 `FileHandle.write` 没 bind** → `TypeError: Illegal invocation` 被账本的 catch 吞成「没落盘」，表现为「所有写入静默失败」且极难定位。故压缩失败那档刻意走**真 IO**（`.tmp` 预置成目录），不让整档韧性依赖 mock。

## 平台差异：Windows 上信号触发不了优雅停机

- **实测事实（Windows + Node 22，本仓主战场）**：`process.kill(pid, "SIGINT")` 与 `"SIGTERM"` 都被 libuv 映射成 `TerminateProcess` —— 目标进程**当场硬退出（exit code 1），Node 侧的信号处理器根本不执行**，于是 `src/server/index.ts` 里那些 `[shutdown] …` 行一条都不会出现，优雅停机路径（`stop()` → 排空连接 → `closeTrafficLedger()` → `logger.flush()`）**一步都没走**。`process.kill(pid, "SIGBREAK")` 更直接：libuv **不支持**用 `process.kill` 把它 raise 出来，抛 `ENOSYS`（实测子进程照常活到自己的超时）。`taskkill` 不带 `/F` 同样是硬终止。`bindSignals` 在 win32 上确实注册了 `SIGBREAK`（`src/server/index.ts`），但它只能由**真实控制台的 Ctrl+Break** 触发，测试里制造不出来。
- **为什么必须单独记一条**：它制造的是**假绿**而不是红。写「停机必须落盘」这类断言时用信号触发，被测逻辑在 Windows 上**压根没执行**，而「文件内容没变化」之类的断言照样通过 —— 等于静默测了个假的。同理，「信号发出后进程还活着片刻」「文件在信号后仍然完整」都**不构成**优雅路径被走过的证据。
- **两种正确写法**：① 需要「停机必落盘 / 停机必 flush」这类断言时，**一律用可控的 `stop()` 调用**（`await runtime.stop()` / `await proxy.stop()` / `await server.stop()`）—— `helpers/proxy.ts:withProxy` 的 `finally`（`await p.stop()`）与 `integration/traffic-ledger-runtime.test.ts` 的停机落盘档走的都是这条，它与 SIGINT 最终调用的是**同一个** `ProxyServer.stop()`；② 确实只能经信号触发时，**显式标注该平台未验**（`it.skipIf(process.platform === "win32")`，或至少在用例注释里写明「Windows 未验：信号被映射为 `TerminateProcess`，处理器不执行」）。**不要**留一条「在 Windows 上静默通过」的信号用例。

## 零外网依赖（`unit/` `integration/` `library/` 的硬约定）

**不变量：`tests/{unit,integration,library}/**` 下的任何用例都不得把连接打到公网。** 需要真网络时，正确做法**永远**是起本地源站：`helpers/net.ts:getFreePort()` 取本机端口 + `helpers/certs.ts` 的仓内测试 PKI（`TEST_TLS_CERTS` / `TEST_CA_PATH`）做 TLS，模式照抄 `helpers/upstream-stub.ts` 与 `tests/http-test-server.mjs`。`manual/` 与 `perf/` **按设计就该打真网络**（`pnpm test:server` / `test:pressure`），不在本约定内。

- **为什么是硬约定（真实踩坑，不是假想）**：`integration/http-proxy-node.test.ts` 的 wss 档打的是外网 `ws.postman-echo.com`，实测单次 TLS 握手约 **4.2s**，而那条用例自己的超时预算只有 **5s** —— 于是并行跑 75 个测试文件时**必然偶发超时**（连续两次全量跑各撞上一次，单独跑通过）。**一个外网依赖是定时炸弹，一组是地雷。** 修法是换本地源站（`wssViaConnect` 的预算原样不动，实测本地端到端 **58ms**），**不是**放宽超时、也**不是** `it.skip`。
- **护栏**：`unit/no-external-network.test.ts`（11 例）+ 扫描器与白名单 `helpers/external-network-scan.ts`。分两面：
  - **A 面（拨号位，零白名单）**：建链原语（`net.connect` / `net.createConnection` / `tls.connect` / `http[s].request` / `http[s].get` / `fetch` / `dns.*`）**实参里被真正拨号的**那个 host 字面量不许是公网 host。这层有牙齿。**A 面的口径必须精确到「拨号位」**，不能退化成「实参里出现的一切字面量」—— 那样 `http.request({ host: "127.0.0.1", …, headers: { Host: "example.com" } })` 会立刻假阳性：`Host` 是 **HTTP 头**（线上文本），`host` 才是**连接目标**；大小写敏感地只认小写选项键 `host`/`hostname` 正好把两者分开。选项对象形态只扫**顶层**键；位置参数形态（`net.connect(port, host, cb)`）才取全部位置字面量。**刻意不纳入** `servername`（SNI 是 TLS 名字，不产生外呼）与 `headers.Host`，它们由 B 层兜住。
  - **B 面（普查 + 显式申报）**：每个公网 host 字面量都必须有 **(file, host) 级别**的豁免 + 理由，写在 `PUBLIC_HOST_ALLOWLIST`。它抓的是 A 面**看不见**的形态 —— **host 作为本地 helper 的实参**（踩过的那档就是 `wssViaConnect(port, "<公网 host>", 443)`，它在文本上与「名单条目字符串」无法区分，只能靠「必须申报」这道人工闸门）。B 面**双向**断言：未申报即红，**豁免失效也红**（否则这张表会腐烂成什么都往里塞的黑洞）。
- **扫描口径三条（改扫描器前必须知道，缺一条就得出错误结论）**：
  1. **先 `codeOnly` 去注释**（复用 `helpers/source-scan.ts` 同一份实现）。注释里点名被禁 host 是在**描述这条不变量本身**。**这不是理论风险，本仓真踩过**：一条 `// …外网 ws.postman-echo.com:443…` 的处置记录里带了反引号，朴素的引号扫描会把注释内容吞成「字符串字面量」，凭空造出一条违规命中。
  2. **只在字符串字面量内部匹配 host**。成员访问（`entry.name` / `log.info` / `context.store` / `h.at`）与 host 在语法上无法区分 —— `name`/`store`/`at`/`ca`/`info` 都是**真实 TLD**，靠字面量边界把前者剔掉。残留误报（字符串里恰好写着 `c.name` 这种**非 host 文本**）走白名单豁免并写明理由，**不靠缩小 TLD 表让噪声消失** —— 那等于给「漏检公网 TLD」开后门。
  3. **「公网」的定义**：顶级域不在 RFC 2606/6761 保留集（`test`/`example`/`invalid`/`localhost`/`local`/`onion`）内；IPv4 排除回环/私网/链路本地/组播/越界 octet。**`example.com` 算公网**（它在 `.com` 之下、真的可解析，是本仓最可能意外拨出去的那个 host）；`192.0.2.43` / `203.0.113.9` / `198.51.100.5`（RFC 5737 文档 IP）也算。
- **白名单纪律**：按**文件**聚合（`{ file, hosts[], reason }`），但断言仍按 (file, host) 集合比对 —— 所以「在已豁免文件里新加一个 host」照样变红。**每条 `reason` 必须回答「它为什么不会建链」**，不许写「测试用」这种废话。**已知的两类合法豁免**：`c.name` / `sub.name` / `fwd.name` / `context.store` 这类**非 host 文本**（因 TLD 表收录 `name`/`store` 被命中），以及 `mple.com` —— 后者是**畸形 host 负向输入**的尾巴（原文 `exämple.com` 含 IDN 字符、`exa mple.com` 含空格，扫描器的 label 字符集不含非 ASCII/空格，只匹到这一段）。
- **扫描器与白名单刻意住在 `helpers/`**（不在扫描范围内）：白名单必须写出被豁免的公网 host 字面量，若它自己被扫描就是纯自噬。推论：**断言档自己不允许出现任何公网 host 字面量**（探针样本全在 helper 的 `SELF_CHECK` / `LITERAL_PROBES`）—— 断言档必须与被断言的仓一样干净。分工与 `helpers/source-scan.ts` 同构：**文本面在 helper，断言在 `unit/`**。
- **防假绿**（三条，缺一条这套护栏就可能在「扫描器坏了」的状态下全绿）：扫描范围非空且覆盖三个目录、且**不**含 `helpers/` `manual/`；A 面扫到的建链调用点 > 30 处且覆盖 ≥3 种原语；B 面扫到的公网引用 ≥ 50 条。**已用变异测试验证**：往 `tests/integration/websocket-single-path.test.ts` 塞 `net.connect(443, "ws.postman-echo.com")` + 一处 helper 实参位 → **A/B 两面同时红**，报错文本直接贴出命中行。

## 测试不落盘

- 默认测试 logger 为 noop，或通过 `silenceLogs()` 把显式 `testConfigStore` 的 console/file 等级与路径静音。需要断言日志的用例必须注入自己的 `LoggerImpl`/config-bound logger 并把 `logFile` 指向临时目录；禁止依赖默认 logger 从生产 store 读取策略。
- **账本目录必须**逐例**隔离（Phase 5b-2 踩过的真实污染）**：用量现在是**持久**的，共享一个 `quotaLedgerDir` 会让上一条用例烧掉的额度漏进下一条。实测症状是 `traffic-quota.test.ts` 的 `[quota-exceeded] … usage=5000` 变成 `usage=15000`，而且**时序相关**（上一条 runtime 的停机落盘有没有赶上本条 `start`），表现为「时红时绿」——最难查的那种污染。修法与隔离 `logFile` 同形：在 `beforeEach` 里 `set("quotaLedgerDir", path.join(<本例临时目录>, "quota"))`，并把 `quotaLedgerDir` 加进该文件的 `KEYS` 快照表随 `restoreConfig` 复原。**根因是真实的、正当的行为**（账本按设计跨进程存活），不要去改账本来「迁就测试」。
- `setup-env.ts` 同时钉 `process.env.QUOTA_LEDGER_DIR` / `set("quotaLedgerDir", …)`（Phase 5b-2）：账本目录与前三项同一纪律但**性质更糟** —— 前三项只是「读到脏数据」，账本目录是**往仓库里写文件**（FIELDS 缺省是相对路径 `cfg/quota`，经 `createConfigContext` 绝对化后落在仓库内）。5a 的 `integration/traffic-quota.test.ts` 有十余条「真起 runtime + 真配非全 0 配额」的用例，不钉的话第一次跑就留下一个未跟踪的 `?? cfg/quota/`（真实踩过一次，已同时加进 `.gitignore` 作第二道保险）。需要断言账本内容的用例自己 `set("quotaLedgerDir", <temp dir>)`。

- `integration/tls-client-auth.test.ts` 显式注入 `new LoggerImpl({ level: "silent" })` 并 spy 该实例的 `warn`，确保 `[tls-client-error]` 断言不依赖任何全局 logger；注入实例的类名是 `LoggerImpl`——历史别名 `Logger` 已从 barrel 删除（`type Logger` 接口仍在，类型位置照旧用）。`integration/log-structured.test.ts` 用 `testConfigStore` 创建 `ConfigContext`、配置临时 `logFile`，经 `ProxyServer({ context })` 验证 JSONL。
- 同理，`aclFile` / `authUsersFile` 钉成不存在的绝对路径，避免开发者本地 `cfg/*.json` 混进测试。需要名单/账号的用例自行 `set(...)` 或创建显式 context；给子进程传 CLI 时仍按 argv > 显式 env > env 文件 > defaults。
